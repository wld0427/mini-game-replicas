# 功能审计报告 — Townscript 城痕

> 审计日期：2026-11-27 · 审计范围：`games/townscript/`
> 方法：README 承诺逐条核对 → 源码比对 → 逻辑层脚本穷举 → Chromium 真实驱动页面
> **审计时测试 36+3 全绿** —— 即以下全部是「测试通过但游戏有洞」的问题。
> 本文件只记录问题，修复由后续轮次按 `docs/process/README.md` 的四道门禁执行。

## 总体判断

**有 P0 存档级缺陷**：城镇代码不记录拓地等级，导致**玩家拓地后刷新页面，整座城被静默丢弃**；
「自由 / 每日」模式切换会**直接覆盖存档**，玩家辛苦建成的城永久消失。
上下文生成规则本身（十种地标的可达性）经穷举验证是完整的，不属于本轮问题。

## A. 功能失效（P0，本轮必修）

| 编号 | 功能 | 问题 | 证据 | 建议 |
| --- | --- | --- | --- | --- |
| A-1 | 城镇代码往返（拓地后） | **拓地升级后的城镇代码无法还原**。`decodeTown()` 固定用 `createTown(seed, 0)` 建城，而长度校验按 level 0 的网格算，于是拓地等级 ≥1 的码一律 `parts[2].length !== town.heights.length` → 返回 `null` | `src/logic.js:500-502`；**浏览器实测**：注入 expand=2 的档案 → 建 3 块 → 刷新 → `.block` 数量由 3 变 **0**，整座城被替换成初始岛 | 城镇代码要带上拓地等级（格式升到 TS2，同时兼容解码旧 TS1）；`createTown` 的返回值里要记住 `expandLevel` |
| A-2 | 存档可靠性（拓地后刷新） | A-1 的直接后果：启动时 `const decoded = decodeTown(savedTown); if (decoded) town = decoded;`，解不出来就**静默沿用初始岛**，玩家没有任何提示 | `assets/app.js:692-696`；浏览器实测同上 | 随 A-1 一并修复；解码失败要有 toast 提示，不能静默吞掉 |
| A-3 | 自由 / 每日模式切换 | **切换模式直接丢弃玩家建的城**。`modeToggle` 的处理器把 `town` 整个换成新建的岛，紧接着 `saveAll()` 把这座空城写进存档；再切回来走的是 `pickSeed()`（随机种子），于是原城**永久消失** | `assets/app.js:574-583`；**浏览器实测**：建 3 块 → 切到每日模式 → `.block` 变 0 → 切回自由模式 → 仍是 0，且存档码与切换前不同（已被新种子替换） | 两种模式各存各的城（自由岛 / 当日岛分开存档），切换只是换读哪一份，不再重新生成 |

## B. 体验缺陷（P1，本轮必修）

| 编号 | 功能 | 问题 | 证据 | 建议 |
| --- | --- | --- | --- | --- |
| B-1 | 每日模式状态 | `dailyMode` 只是内存变量，**刷新后丢失**：界面显示「自由模式」，存档里装的却是每日岛的城，玩家分不清自己在哪座岛上；在每日岛建的楼还会被当成自由岛存档 | `assets/app.js:78`（无持久化）、`:422-429`（提示按 dailyMode 取）；浏览器实测：切到每日模式后刷新，`aria-pressed` 由 `true` 变 `false` | 模式状态要持久化；并与 A-3 的分岛存档配合 |
| B-2 | 城镇代码的建造计数 | 代码不保存 `builds` / `removals`，还原一座分享来的城后计数归零 → **下一次建造会重新触发「初基」里程碑**（白嫖一条收集物），建造统计也会归零 | `src/logic.js:484-488`（只编码 seed/高度/颜色）；脚本实测：往返后 `builds` 由 3 变 0 | 代码里带上计数（与 A-1 的格式升级一起做） |

| 编号 | 盲区 | 问题 | 证据 | 建议 |
| --- | --- | --- | --- | --- |
| C-1 | 存档往返只测了 level 0 | 现有往返测试用 `createTown(seed, 0)`，永远撞不到 A-1 | `test/logic.test.mjs` 城镇代码段 | 补「拓地等级 ≥1 的城镇代码可往返」用例 |
| C-2 | 模式切换无任何用例 | 没有任何测试覆盖「切换模式后城还在不在」 | 全工程无相关断言 | 补端到端用例：建块 → 切模式 → 断言块还在 → 切回 → 断言还是原来那座城 |

| C-4 | 地标可达性无系统验证 | 十种地标各自有单测，但没有「每一种都能真的被造出来」的整体验证 | `test/logic.test.mjs` 逐条规则测 | 补一组穷举可达性用例（本轮审计脚本已验证十种全部可达） |

## D. 已核验为「不是问题」（避免误改）

| 怀疑点 | 核验结论 |
| --- | --- |
| 「拱廊」地标不可达 | **可达**。规则是「左右无建筑、上下有建筑」，不是「左右是水」——因为画面上所有格子都是海（按深度上色），不存在「陆地格子」的概念。审计脚本第一次构造写错了（同时要求四邻为空又要求上下有建筑），修正后可达 |
| 「里程碑只有 2 条，地标有 10 种」 | **不是问题**。`MILESTONES` 是「每种地标的里程碑类型」（初次建起 / 五度匠心），图鉴完成度按 `10 × 2 = 20` 计算，`dexProgress()` 实现正确 |
| 「地脉 ×3 铜钱」「调色解锁」「勘测提示」 | 逐条核对实现无误：地脉倍率在 `doBuild` 里生效、调色板按 `paletteSize` 锁定、`findHint` 探测后正确还原状态 |

## E. 打磨与一致性（P2，本轮可做）

| 编号 | 项 | 说明 |
| --- | --- | --- |
| E-1 | 城镇代码格式没有演进空间 | 现在固定 `TS1-种子-高度-颜色` 四段，加拓地等级就必须升版本；本轮升到 `TS2` 并保留旧码解码 |
| E-2 | 解码失败静默吞掉 | 解码失败时界面无任何提示，玩家只会以为「刷新后城没了」 |

## 修复优先级建议

| 优先级 | 项 |
| --- | --- |
| P0 | A-1 城镇代码带拓地等级、A-2 存档能读回来、A-3 切换模式不丢城 |
| P1 | B-1 每日模式持久化、B-2 代码带建造计数 |
| 测试 | C-1 ~ C-4 |
| P2 | E-1 格式升级、E-2 解码失败提示 |
