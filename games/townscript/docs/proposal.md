# 立项评审 — Townscript 城痕

> 评审视角：**存量修复**。本文回答「这一版要补齐什么、凭什么值得留」。
> 审计依据：`docs/audit/townscript.md`（审计时 36+3 测试全绿，但存在 3 条 P0 存档级缺陷）。

## 一句话定位

点一块海面起楼，**邻居的形状决定它长成什么**，把十种地标从上下文规则里钓出来。

## 为什么做它

同类「上下文生成」沙盒（Townscaper 一类）的通病是：**玩家和生成器之间的关系是单向的**。
点一下，规则替你决定形态；规则本身没有历史，你没法「经营」一座城，只能不断试错。

本作把**上下文规则本身变成可收集物**：十种地标不是随机刷新的奖励，而是**由邻居关系推导出来的必然结果**。
同一个配方永远长出同一种东西，所以城可以被编码成一段文本发给别人。

**但存量版本没能兑现这个承诺。** 审计查出：城镇代码不记录拓地等级，
于是**玩家拓地后一刷新，整座城被静默丢弃**；「自由 / 每日」模式切换会**直接覆盖存档**，
辛苦建成的城永久消失。这不是「体验粗糙」，是**玩家攒了几十分钟的成果说没就没**。

这一版要做的，是把存档这条地基修牢，并让「分享一座城」这个核心承诺真正成立。

## 核心亮点

**亮���一：邻居决定形态，形态可以当收集物。**
水面上立起四块 1×1 的方块，方场（plaza）自动成立；把其中一块叠到第三层，
它变成孤塔（spire）；给它涂上和邻居交替的配色，细高塔身变成灯塔（lighthouse）。
玩家做的事是「摆」，得到的却是「发现」——十种地标 × 两条里程碑 = 20 件收集物。
落实在 `src/logic.js` 的 `matchLandmarks()` / `detectNeighborhood()` 与 `countLandmarks()`。

**亮点二：整座城压成一段文本。**
`TS2-种子-拓地-建造-拆除-高度-颜色`，一座城就是一行 ASCII。
发给朋友，他打开就能看到你摆的那座城，连同一块地基都没变。

## 核心循环引擎

**主引擎：`sandbox-explore`（沙盒探索）**

- **目标线**：把十种地标全部发现，并让图鉴完成度推到 20/20；同时把城镇代码分享出去。
- **Hard Fail**：没有失败条件 —— 这是沙盒，玩家的失败只体现在「没发现」与「城丢了」上。
  所以本轮的工作重点正落在**保证沙盒的成果不会消失**（存档可靠），
  否则沙盒引擎的「积累」部分直接失效。

**辅引擎：`progression-rng`（进度 + 随机）**

- **目标线**：铜钱 → 工坊升级（拓地 / 调色 / 勘测 / 营建）→ 更宽的图、更高的楼、更准的勘测。
- **Hard Fail**：铜钱必须来自建造行为本身（每块地基 +1、命中地脉 ×3、新地标 +12），
  且**挂机不能刷钱** —— 不建造就没有收入（见 `docs/design.md` 的难度契约）。

## 独特钩子

**Signature Twist（签名钩子）：规则即掉落物。**
一般沙盒里，「发现」是系统随机给的奖励；本作里，**发现的是你自己搭出来的结构**：
方场不是抽到的，是你用四块石头摆出来的；灯塔不是刷到的，是你在孤塔旁边换了个颜色撞出来的。
落点：`src/logic.js` 的 `matchLandmarks()` —— 判定完全由 `cellFacts()` 的邻居统计推导，
`src/logic.js` 的 `countLandmarks()` 负责把判定结果变成可收集的计数。

**Peak Moment（峰值时刻）：一次落子点亮一整片图鉴。**
在空地上铺出 2×2 的方块的那一瞬间，方场判定在四格里同时成立，
图鉴里「方场 · 初次建起」与「方场 · 五度匠心」连着跳出来，铜钱和 toast 一起冒出来。
落点：`assets/app.js` 的 `doBuild()` —— `fresh`（前后计数差）决定哪些地标是新发现的，
`applyEvent()` 逐条比对里程碑前后状态并返回 `milestones` 数组，`announce()` 负责同时播报。

## 参考调研

只记结论，不搬运源码与素材。

| 参考 | 核心循环与签名张力 | 空间布局与信息可见性 |
| --- | --- | --- |
| Townscaper | 核心循环是「落子 → 上下文推导 → 形态涌现」，签名张力在于**玩家不直接选择形态，而是选择关系**；形态是副产品，所以每次落子都有「我造出了什么」的发现感 | 2.5D 斜堆是它的空间语言：越高越往右上偏，靠偏移量制造高度错觉；**同一套几何必须同时服务渲染与命中检测**，否则「看起来是哪一格」和「点下去算哪一格」会打架 |
| 增量经营类（Townscaper 的经营外层 / 城市建造类） | 核心循环是「投入 → 产出 → 解锁更大空间」；签名张力是**解锁后的空间变大，之前精心摆的布局却要在新空间里重新理解** | 空间布局上，进度类 UI（钱 / 等级 / 收集度）必须**常驻且可扫读**，否则玩家要在「摆」与「看账本」之间反复切注意力 |

结论落到本作：
1. **形态必须由规则推导，不能由玩家直接点选** —— 这正是 `matchLandmarks()` 的做法，也是收集感的来源。
2. **渲染与命中检测共用 `VIEW.cell / VIEW.off / VIEW.gap`** —— 本作已如此实现，必须保持，
   改动斜堆参数时两条路径要同时改，否则会出现「点不中自己看到的楼」。
3. **拓地升级会改变网格尺寸** —— 这正是本次 P0 的根因：**任何改变世界尺寸的升级，
   都必须同时进入存档格式**，否则玩家一升级就丢城。

## 独特玩法

**「上下文规则」把建楼从摆放变成解谜。**
玩家的操作只有一个：在一格里落一块石头（或把已有的格子叠高、涂色、拆掉）。
但结果形态由十套邻居规则推导，且一条格可以同时命中多种地标（优先级决定显示哪一个）。
于是「我想造一座灯塔」这件事变成了一道**约束求解题**：塔身要细高（四邻只有一个等高邻居）、
颜色要和邻居交替、还得是第三层以上。

同时，**建造/拆除次数会进入城镇代码**，所以「一座城」不只是地形快照，还带着作者的施工历史。

## 表现力

- **视觉**：海岛黄昏主题，全 SVG 自绘。海水按深度值混色（深蓝→青绿），建筑是带斜堆偏移的方块，
  10 种地标各有专属装饰图形（孤塔的尖顶、灯塔的光束、码头的缆桩…）。
- **动效**：落子有高度变化动画，地标达成时 toast 播报，图鉴格子点亮。
- **音效**：WebAudio 现场合成 —— 建造按层数变调的落块声、拆除的碎裂声、地脉上的特殊音。

## 差异化

- **与仓库已有游戏对比**：最接近的是 `ball-foundry`（落球坊），同为「确定性模拟 + 增量经营 + 图鉴里程碑」。
  区别在于 ball-foundry 的操作是**空间投放**（扔球、堆叠），本作的操作是**在格子上落子并改变邻居关系**；
  ball-foundry 的产出是「球堆成了什么形状」，本作的产出是「这堆房子被规则认成了什么地标」。
  与 `angler-almanac`（渔汛录）相比，那款是概率 + 时机窗口，本款是确定性的上下文推导 —— 本作**没有随机掉落**。
- **与候选池对比**：候选池里的「元素周期表配对」「2048 变体」「反应力测试」都是纯规则或纯反应，
  没有「玩家产物可编码分享」这一层；本作的城镇代码是天然的内容载体。

## 可测性

核心玩法**全部可以脱离浏览器确定性表达**，规则落在 `src/logic.js`（零 DOM 依赖）：
岛屿生成 `createTown()` / `valueNoise()`、上下文规则 `matchLandmarks()` / `cellFacts()`、
命中检测 `hitTest()` / `blockRect()`、城镇代码 `encodeTown()` / `decodeTown()`、
档案与图鉴 `applyEvent()` / `dexProgress()`、存档 `serializeProfile()` / `deserializeProfile()`。
随机全部走固定种子的 mulberry32 —— 同一种子必然长出同一座岛，城镇代码能互相分享。

本轮要补的不变量：
- **每种地标都能被真的造出来**（穷举可达性，而不是逐条规则各自测）；
- **任意拓地等级的城镇代码都能往返**（高度、颜色、拓地等级、建造计数全部一致）；
- **切换模式后城还在**，且切回来还是原来那座城（端到端，浏览器里验）；
- **刷新后模式与城都还在**。

## 风险与代价

1. **存档格式升级（TS1 → TS2）会让旧存档里的城读不出来。**
   兜底：保留 TS1 的解码分支（旧码按拓地等级 0、计数 0 还原）；
   旧码对应的城本来就是 level 0 的网格，能原样还原，不丢城。
2. **模式分离存档会让「每日岛」在换天后重置。**
   兜底：这是设计意图（每天同一座新岛，全服可比），且每日岛按日期单独存档，
   当天的进度不会因为切换模式而丢；跨天清空要在界面上写明。
3. **修「切换模式丢城」可能引入新的交互困惑**（玩家建完切换，回来发现城还在，会不会以为没切换）。
   兜底：切换时给 toast，明确提示切到了哪座岛；模式按钮的状态与提示文案同步更新。
4. **改动存档格式会牵动存档读写两处**，容易漏。
   兜底：往返用例必须覆盖「TS1 旧码」「TS2 新码」「非法码」三种输入。

## 结论

结论: 通过

核心理由: 「规则即掉落物」这条钩子让建楼从摆放变成解谜，整座城又能压成一段文本分享 ——
这个组合值得留；但存量版本的存档会在「拓地后刷新」和「切换模式」这两个最日常的操作上毁掉玩家的成果，
**沙盒引擎的积累部分直接失效**，因此这一版把存档修牢是让这个设计真正成立的必要条件，而不是锦上添花。
