# 开发计划 — Townscript 城痕

## 总览

本轮目标：把存量首版的城痕补到**四道门禁全绿**，而且补的是**真功能**而不是补文档。

审计（`docs/audit/townscript.md`）查出本作有 **3 条 P0 存档级缺陷**：
拓地后刷新整座城被丢弃、切换模式永久覆盖存档、每日模式状态刷新即丢。
这一版把存档这条地基修牢，并补上「分享一座城」这个核心承诺。

四个阶段串行推进，前一阶段的验收命令跑绿才允许开下一阶段。

| 阶段 | 目标 | 产出 |
| --- | --- | --- |
| 1 | 文档地基：立项评审 + 功能设计 + 开发计划 | `docs/proposal.md` `docs/design.md` `docs/plan.md` |
| 2 | 修 P0/P1 + 补行为测试 + 建立四向追溯 | `src/logic.js` `assets/app.js` `assets/data.js` `test/*.test.mjs` |
| 3 | 交付验收：双端截图人工核对 + 验收记录 + 部署 | `docs/acceptance.md` + `docs/shots/` + 部署 URL |

## 阶段

### 阶段 1：文档地基

**做什么**：按 `docs/process/` 模板写三份文档，把 20 项功能清单定下来。

**产出文件**：`games/townscript/docs/proposal.md`、`design.md`、`plan.md`

**验收命令**：

```bash
node scripts/design-review.mjs games/townscript
```

**期望输出**：

```
✓ townscript — 立项评审 / 设计文档 / 开发计划 齐备且达标

✓ 设计评审全部通过。
```

**完成标准**：设计评审退出码 0，且 `design.md` 的功能清单能被 `scripts/feature-trace.mjs` 解析出 20 个 F-ID。

---

### 阶段 2：修 P0/P1 + 补行为测试

**做什么**：

1. **修 A-1（城镇代码往返）**：`createTown()` 的返回值记住 `expandLevel`；
   `encodeTown()` 升到 `TS2-种子-拓地-建造-拆除-高度-颜色`；`decodeTown()` 按码里的拓地等级建城，
   并保留 `TS1` 旧码的解码分支。
2. **修 A-3（切换模式丢城）**：自由岛与每日岛各存各的存档键，模式切换只换读哪一份，不再新建城。
3. **修 B-1（每日模式持久化）**：模式状态存进 `localStorage`，刷新后仍在原来的岛。
4. **修 B-2（代码带建造计数）**：随 A-1 一起做进 `TS2` 格式。
5. **补 E-2（解码失败提示）**：解析失败给 toast，不再静默吞掉。
6. **给 20 项功能在代码里加 `@feature` 标记、在测试里加 `@covers` 标记**，
   并补上审计指出的 4 处测试盲区（拓地往返 / 模式切换 / 刷新保持 / 地标可达性）。

**产出文件**：`games/townscript/src/logic.js`、`assets/app.js`、`assets/app.css`、
`assets/i18n.js`、`index.html`、`test/logic.test.mjs`、`test/smoke.test.mjs`

**验收命令**：

```bash
cd games/townscript && node --test "test/*.test.mjs"
node scripts/review.mjs games/townscript
node scripts/feature-trace.mjs games/townscript
```

**期望输出**：

```
# tests 48
# pass 48
# fail 0

✓ 静态审查通过：检查了 1 个项目，未发现问题。

✓ 功能追溯矩阵完整：无缺失实现、无缺失测试、无缺失验收、无孤儿实现。
```

**完成标准**：三条命令全部退出码 0；功能追溯矩阵 20 项全部 ✅；
**三条 P0 必须各有端到端用例**（拓地后刷新城还在、切换模式城还在、刷新后模式还在），
只测纯函数不算数。

---

### 阶段 3：交付验收

**做什么**：

1. 桌面 + 移动双端截图人工核对（布局错位、遮挡、文字截断、按钮反馈），逐条写验收记录。
2. 截图核对中发现的问题必须**当场改代码**，不只写进「已知问题」。
3. 截图用「拉高视口再截」而非 Playwright `fullPage`，避免 sticky 顶栏的拼接伪影造成误判。

**产出文件**：`games/townscript/docs/acceptance.md`、`docs/shots/*.png`

**验收命令**：

```bash
node scripts/gate.mjs games/townscript
curl -s -o /dev/null -w '%{http_code}\n' https://<部署域名>/
```

**期望输出**：

```
  ✓ 静态代码审查 — 检查了 1 个项目，未发现问题
  ✓ 立项评审 + 设计文档 + 开发计划
  ✓ 功能追溯矩阵（设计 ↔ 实现 ↔ 测试 ↔ 验收）
  ✓ 全量测试
  ✓ 追踪表登记完整 — 6 款均已登记
  ✓ 标记为「已交付」的项目均通过门禁

✓ 总门禁通过。
```

**完成标准**：总门禁退出码 0；双端截图已人工看过并修掉发现的问题；部署后首页 200。

## 阶段门禁规则

- 阶段 1 不绿 → 不许写代码（否则功能清单会与实现脱节，追溯矩阵失去基准）。
- 阶段 2 不绿 → 不许写验收记录（没有测试背书的验收是假的）。
- 阶段 3 不绿 → **不许开始下一款游戏**。

## 风险登记

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 存档格式升到 TS2 后旧存档读不出来 | 中 | 高 | 保留 `TS1` 解码分支（旧码按拓地等级 0、计数 0 还原，旧城不丢） |
| 模式分离存档后，玩家以为「切了没反应」 | 中 | 低 | 切换时 toast 明确提示切到了哪座岛；模式按钮状态同步 |
| 每日岛跨天清空被误当成 bug | 中 | 中 | 界面写明「每日岛每天换一座」，并按日期分键存档，当天进度不因切换而丢 |
| 断言写成「函数存在」式糊弄 | 中 | 高 | 每条断言都检查**返回值内容**（逐格数组相等、计数变化、字符串相等），不检查函数是否定义 |
| 追溯矩阵出现孤儿实现 | 低 | 高 | 先定稿 design.md 再加标记，标记与清单一一对应 |
