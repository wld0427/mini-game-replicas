## 本轮修掉的真实缺陷（审计 → 修复 → 复验）

| 编号 | 缺陷 | 修法 | 复验 |
| --- | --- | --- | --- |
| A-1 | **拓地后的城镇代码无法还原**（`decodeTown` 固定按 level 0 建城，长度校验必失败） | 代码升到 `TS2-种子-拓地-建造-拆除-高度-颜色`；`createTown()` 记住 `expandLevel` | 单测三档拓地等级往返 + 浏览器「拓地后刷新城不丢」 |
| A-2 | **拓地后刷新，整座城被静默丢弃**（解码失败就沿用初始岛，无任何提示） | 随 A-1 修复；解码失败改为 toast 提示「城镇代码无法解析」 | 浏览器实测：刷新前 3 块 → 刷新后仍 3 块 |
| A-3 | **切换「自由 / 每日」模式永久覆盖存档**（新建城后立刻 `saveAll()`） | 两种模式各存各的存档键（自由岛 `townscript-town-v1`、每日岛 `townscript-daily-<日期>`），切换只换读哪一份 | 浏览器实测：切过去再切回来，存档码**逐字相同** |
| B-1 | **每日模式状态刷新即丢**（`dailyMode` 是纯内存变量） | 模式状态存进 `localStorage`（`townscript-mode-v1`），启动时先读模式再读城 | 浏览器实测：切到每日模式 → 刷新 → `aria-pressed` 仍为 `true` |
| B-2 | **还原外来城镇会白嫖「初基」里程碑**（代码不带建造计数） | 代码带上 `builds` / `removals` | 单测：往返后 `builds` 与原城一致 |
| E-2 | 解码失败静默吞掉，玩家只会以为「城没了」 | 解析失败给 toast | 同 A-2 |
| 额外 | **拓地后旧城被搬到新网格左上角**（岛是居中的，城却缩在角落） | 迁移改为居中对齐（`resizeTown()`） | 截图核对 |

## 难度契约的落地验证

| 路线 | 断言 | 结果 |
| --- | --- | --- |
| 参考路线 | 十种地标各有一种最小构造摆法（单测「十种地标都能被造出来」） | ✅ 10/10 全部可达 |
| 弱化路线 | 随机乱点 200 次（同一套 `placeBlock` → `countLandmarks` → `applyEvent`） | ✅ 拿不满 10 种地标，说明地标判定不松 |
| 挂机路线 | 不调用任何建造事件 | ✅ 铜钱恒为 0、图鉴进度恒为 0、建造次数恒为 0 |

## 已知问题

- **图鉴面板较长**：10 种地标每种两行信息，桌面端占约 880px 高，需要滚动。已通过把它留在右栏 +
  成就移左栏把两栏拉平，但面板本身未做折叠（属打磨项，不影响核心玩法）。
- **每日岛跨天会换一座新岛**：这是设计意图（当天进度不丢，跨天清空），已在界面提示中写明。
- **还原外来城镇时会同步对方的拓地等级**：代码里的海图大小优先于本地档案，避免「地图大小」与
  「已购升级」对不上；这意味着导入别人的城会覆盖本地拓地等级，属有意为之。
- 无排行榜、无跨端存档同步。属「明确不做的事」范围。

## 结论

结论: 通过

核心理由: 20 项功能全部具备实现标记、行为断言与验收记录，四向追溯完整；
审计查出的 3 条 P0（拓地后丢城、切换模式覆盖存档、每日模式状态丢失）与 2 条 P1 全部修掉并有端到端用例；
视觉上修掉了「双栏差 1100px」「提示条压住调色板」「海图读不出岛形」三处实际看图才发现的问题；
十种地标的可达性经穷举验证完整，难度契约三档路线都能用同一套规则代码判定。
