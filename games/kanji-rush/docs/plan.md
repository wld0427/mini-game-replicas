# 开发计划 — Kanji Rush 汉字扭蛋

> 本计划记录的是 2026-11-26 存量修复轮的实际执行路径（首版实现路径见 git 历史）。
> 阶段为串行门禁：上一阶段验收命令跑绿才允许开下一阶段。

## 总览

拆法是「先把可测的核心规则钉死 → 再把界面接到规则上 → 最后打磨观感」：
核心规则必须能确定性单测，否则后面所有功能都建立在无法验证的地基上。

## 阶段

### 阶段 1：核心规则可确定性化

- **目标**：把稀有度分档、权重抽取、保底、连击、节奏、成就、存档全部抽成不依赖浏览器的纯函数
- **产出文件**：
  - `src/logic.js`
  - `assets/data.js`
  - `test/logic.test.mjs`
- **实现的功能 ID**：F-001, F-002, F-003, F-004, F-005, F-006, F-007, F-008
- **验收命令**：

  ```bash
  cd games/kanji-rush && node --test "test/*.test.mjs"
  ```

- **期望输出**：`# pass 19`（逻辑层 19 条全绿）
- **完成标准**：19 条逻辑断言全部通过，覆盖分档边界、权重分布容差、保底触发与计数、连击累加与清零、节奏单调性、成就不重复解锁、存档往返与脏数据回退

### 阶段 2：界面接线与交互闭环

- **目标**：把纯逻辑接到 DOM 上，形成"抽卡 → 卡面演出 → 图鉴/统计/成就更新 → 存档"的完整回路
- **产出文件**：
  - `index.html`
  - `assets/app.js`
  - `assets/i18n.js`
  - `assets/app.css`
  - `test/smoke.test.mjs`
  - `test/helpers.mjs`
- **实现的功能 ID**：F-003, F-009, F-010, F-011
- **验收命令**：

  ```bash
  cd games/kanji-rush && node --test "test/*.test.mjs"
  ```

- **期望输出**：`# pass 25`
- **完成标准**：浏览器真实 Chromium 中验证首屏渲染、点击与空格两种抽取、自动模式开关与连续抽取、语言三语切换、刷新后进度保留、控制台零报错、390px 视口无横向溢出

### 阶段 3：追溯体系接入与补齐盲区

- **目标**：建立"设计文档 → 代码标记 → 测试标记 → 验收记录"四向对齐，补上此前完全没有测试的功能
- **产出文件**：
  - `docs/proposal.md`
  - `docs/design.md`
  - `docs/plan.md`
  - `docs/acceptance.md`
  - `src/logic.js`（补 `@feature` 标记）
  - `assets/app.js`（补 `@feature` 标记）
  - `test/logic.test.mjs`（补 `@covers` 标记）
  - `test/smoke.test.mjs`（拆分用例并补 `@covers` 标记）
- **实现的功能 ID**：全部 11 项
- **验收命令**：

  ```bash
  cd /workspace/mini-game-replicas && node scripts/gate.mjs games/kanji-rush
  ```

- **期望输出**：`✓ 总门禁通过。`
- **完成标准**：追溯矩阵 11 项全绿（F-001 ~ F-011），静态审查 0 问题，设计评审 0 问题，全量测试 0 失败

### 阶段 4：视觉与交互打磨验收

- **目标**：把"能用"打磨到"愿意玩"，并把打磨结果固化为截图证据
- **产出文件**：
  - `assets/app.css`（toast 位置、移动端顶栏、按钮断字等修正）
  - `docs/acceptance.md`（视觉验收表 + 截图清单）
- **实现的功能 ID**：F-009, F-010, F-011
- **验收命令**：

  ```bash
  cd games/kanji-rush && node --test "test/*.test.mjs"
  # 另需人工核对桌面 1280×900 与移动 390×844 两张截图
  ```

- **期望输出**：`# pass 25`，且两张截图经逐项核对无布局错位、遮挡、文字截断、按钮无反馈
- **完成标准**：toast 不再遮挡统计栏与抽取按钮；移动端语言按钮不竖排断字；390px 无横向溢出

## 阶段门禁规则

- 阶段 N 的验收命令必须实际运行过并保留输出，不允许"应该能过"
- 任何阶段失败 → 修复后重跑，不允许带着红灯进入下一阶段
- 功能清单发生变化时，先改 `design.md`，再回来同步本文件的阶段划分

## 风险登记

| 风险 | 触发条件 | 应对 | 轮次 |
| --- | --- | --- | --- |
| 随机性导致测试不稳定 | 单测直接用 `Math.random` | 随机源可注入，单测统一用固定种子 mulberry32 | 阶段 1 |
| 音效层无法断言 | 真实 AudioContext 不可观测 | 桩掉 AudioContext 统计振荡器创建数，按档位断言音数分层 | 阶段 3 |
| 演出太快看不清字 | 间隔下限过低 | 下限锁 180ms，传奇加速仅持续 5 次 | 阶段 1 |
| NAS 挂载导致 git 误报 clean | stat 缓存过期 | 提交后用 `git show HEAD:<file>` 复核 | 阶段 3 |
