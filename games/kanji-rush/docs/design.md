# 功能设计文档 — Kanji Rush 汉字扭蛋

## 一句话定位

按汉字的真实使用频次决定稀有度、每抽一次演出就更快一档的汉字扭蛋网页小游戏。

## 核心玩法循环

1. 玩家点「抽取」（或按空格）→ 2. 系统按权重抽一个稀有度档位，再在该档位里抽一个字 →
3. 卡面翻牌演出（字形 + 读音 + 释义 + 档位名），音效随档位变化 →
4. 图鉴新增/累加该字，统计面板与连击更新 →
5. 抽卡数 +1，**自动抽取间隔缩短一档** → 回到第 1 步

长线目标由**图鉴完成度**与**成就**提供；短线上头由**越抽越快**的节奏提供。

## 状态机

| 状态 | 含义 | 转入条件 | 转出到 |
| --- | --- | --- | --- |
| `idle` | 待抽取 | 初始化完成 / 一次抽取演出结束 | `pulling` |
| `pulling` | 演出中（卡面已翻出） | 玩家点击抽取或自动计时器触发 | `idle` |
| `auto-on` | 自动抽取进行中 | 玩家开启自动 | 持续按 `currentDelay` 间隔自转 `pulling` |
| `auto-off` | 手动模式 | 玩家关闭自动 | `idle` |

非法转移：演出进行中再次触发抽取 → 忽略本次输入（不叠加抽取），避免连点导致节奏错乱。

## 数据结构

`GameState`（纯 JS 对象，持久化到 `localStorage`）：

| 字段 | 类型 | 含义 | 默认 | 取值范围 |
| --- | --- | --- | --- | --- |
| `pulls` | number | 总抽取次数 | 0 | ≥ 0 整数 |
| `pity` | number | 距保底还差几次 | 0 | 0 ~ 60 |
| `pityBreaks` | number | 保底触发次数 | 0 | ≥ 0 整数 |
| `combo` | number | 当前连击 | 0 | ≥ 0 整数 |
| `bestCombo` | number | 历史最高连击 | 0 | ≥ 0 整数 |
| `surge` | number | 传奇后加速剩余次数 | 0 | 0 ~ 5 |
| `collection` | Record<string, number> | 字 id → 拥有数量 | `{}` | 值为正整数 |
| `tierCounts` | Record<string, number> | 各档位抽到次数 | 全 0 | ≥ 0 整数 |
| `achievements` | Record<string, boolean> | 已解锁成就 | `{}` | 仅 true |
| `startedAt` | string \| null | 首次开始时间 | null | ISO 字符串 |

`collection` 与 `achievements` 一律使用 **null 原型对象**，杜绝原型污染。

脏数据回退：`deserializeState` 对任何非法字段（字符串、负数、NaN、非法 JSON、非对象）
一律回退为默认值，且只接受白名单内的成就 id。

## 难度契约

本作是纯随机收集游戏，没有"操作技巧"维度，因此三档难度落在**抽卡体验**上：
玩家能不能拿到可见进展、会不会长时间零收获、自动抽会不会失控。三档必须用**同一套 `applyPull` 规则**跑，不得为测试单独造逻辑。

| 档位 | 必须成立 | 怎么验 | 实测 |
| --- | --- | --- | --- |
| 参考路线 | 手动连续抽取 60 次时，第 60 次必定是传说（保底兑现），且过程不卡死 | 单测「保底：连续 PITY_LIMIT 次未出传说则强制触发，且计数归零」；单测「tempoDelay 随抽卡数单调不增，且不低于下限」 | 保底 100% 兑现；间隔下限 180ms |
| 弱化路线 | 一个「只会一直按空格、从不看图鉴」的玩家也要持续拿到可见进展，不会长时间零收获 | 20000 段 × 60 抽的真实模拟（直接调用 `applyPull` + 种子随机源） | 每个 60 抽窗口内至少出 1 张**史诗+**的比例 = **100.000%**；至少 1 张**传说+** = **88.855%**（其余由第 60 抽保底兜底）；普通档实际占比 59.15%，与设定 59.17% 偏差 0.02 个百分点 |
| 挂机路线 | 自动抽取开启后不会把游戏瞬间刷爆，也不会因间隔归零而卡死 | 单测「tempoDelay 随抽卡数单调不增，且不低于下限」：间隔 ≥ 180ms；浏览器用例「F-010 自动模式下空格不再叠加抽取」 | 自动开启时连按 8 次空格，抽取次数增量 ≤ 2 |

补充说明：

- 上表的模拟数字是用游戏自己的 `applyPull()` 跑出来的，不是估算值；复现脚本见「验证命令」段。
- 随机触发类功能的可达性另有独立断言：连击里程碑「50 抽→3 连、200 抽→5 连、1000 抽→8 连」由单测「每个成就都在有限抽数内可达（死成就回归）」守住（历史上"15 连击"的达成概率约 1.9e-13，是一段死代码，已改为"稀有及以上"累加）。
- 「弱化路线有进展」与「挂机路线不失控」是两条**独立断言**，互不顶替。

验证命令：

```bash
cd games/kanji-rush && node --test "test/*.test.mjs"
```

## 功能清单

| ID | 功能 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| F-001 | 稀有度分档 | 按 `freq` 生僻度百分位把 102 个字划入 5 档 | `freq` 为 34/35/57/58/77/78/92/93 时分别归入 n/r/r/sr/sr/ssr/ssr/ur 档 |
| F-002 | 权重抽取 | 按档位权重（100/45/18/5/1）抽稀有度，再在档内抽字 | 固定种子采样 3000 次，各档占比与配置权重的偏差小于 3.5 个百分点 |
| F-003 | 抽取与图鉴 | 一次抽取更新总数、图鉴、档位计数、最近记录 | 执行 1 次抽取后 `pulls` 由 0 变为 1，该字 `collection` 计数为 1，对应 `tierCounts` 加 1 |
| F-004 | 保底机制 | 连续 60 次未出传说及以上时，下一次必出传说 | `pity` 达到 60 时下一次抽取的档位为 ssr，且抽取后 `pity` 归 0 |
| F-005 | 连击计数 | 连续抽到稀有及以上累加连击，普通清零 | 连续 3 次 r 档后 `combo` 等于 3；随后抽到 n 档时 `combo` 归 0；**实测 50 抽内可达 3 连、200 抽内可达 5 连、1000 抽内可达 8 连** |
| F-006 | 演出节奏 | 抽卡数越多，自动抽取间隔越短；出传说后 5 次内再快 20% | `tempoDelay(0)` 返回 1400，`tempoDelay(400)` 不小于下限 180，且相邻两次抽取的间隔单调不增 |
| F-007 | 成就系统 | 9 项成就按进度自动解锁 | 第 1 次抽取后 `first_pull` 的值为 true，且成就解锁总数增加 1；同一成就不会重复解锁；**每一项成就都必须在有限次抽取内可达**（见下方可达性约束） |
| F-008 | 本地存档 | 进度存 `localStorage`，刷新不丢，脏数据安全回退 | 序列化后反序列化，`pulls` 与 `collection` 的内容完全一致；对非法 JSON 字符串反序列化后 `pulls` 归 0 |
| F-009 | 多语言与图鉴呈现 | 中/英/日三语切换，图鉴面板展示 102 格与档位配色 | 切到 English 后抽取按钮文案变为 PULL，图鉴格子数量等于 102 |
| F-010 | 自动抽取与键盘操作 | 自动模式定时抽取，空格抽取，A 切换自动 | 按 A 键后自动状态变为 ON，按空格键后 `pulls` 计数加 1；**自动开启时按空格不额外增加抽取次数** |
| F-011 | 音效反馈 | WebAudio 现场合成音效，不依赖任何外部音频文件 | 抽取时创建的振荡器节点数量不少于 1，出 ssr/ur 时的振荡器数量多于出普通档时 |
| F-012 | 分档分布呈现 | 把各稀有度的累计抽取次数显示在界面上 | 抽取后分档分布条中「普通」的计数与 `tierCounts.n` 相等；共 5 个分档条目 |
| F-013 | 成就达成条件与进度 | 每个成就显示达成条件文案与当前进度 | 成就列表中每项都显示条件文案，未解锁项显示「当前/目标」进度数字 |
| F-014 | 加速状态提示 | 命中传说以上后的 5 次加速窗口内显示加速徽标 | 抽到 ssr 或 ur 后加速徽标可见，`surge` 计数归零后重新隐藏 |
| F-015 | 稀有档演出 | 出传说/神话时既要翻卡入场、又要光晕脉冲，两个动画不得互相覆盖 | 抽到 ssr 或 ur 后，卡面元素的 `animation-name` 同时包含 `card-in` 与 `fever` |

### 可达性约束（随机触发类功能必须遵守）

凡是靠随机触发的功能（成就、稀有度、保底、掉落），**验收标准必须能证明它真的会被触发**，
不能只验证"逻辑存在"。

本项目实例（一次真实的失败）：
连击只在史诗及以上累加，P(史诗+) = 24/169 ≈ 14.2%，因此「15 连击」成就的达成概率
约 1.9e-13 —— 实测 30 万抽最高连击只有 7，**该成就玩家永远拿不到，是一段死代码**。
当时的功能清单只写了"9 项成就按进度自动解锁"，没有要求可达，于是它从网眼里漏了过去。

现行约束：
1. 每个成就的 `goal` 必须落在**可观测概率分布内**，并由单元测试给出可达路径构造；
2. 概率类功能（如保底）必须用**真实状态机路径**触达，不允许在测试里直接改状态伪造；
3. 纯视觉分支（如某档专属动画）必须有**计算样式断言**，因为这类问题不会被"元素存在"型断言发现。

## 边界与异常

| 场景 | 期望行为 |
| --- | --- |
| `localStorage` 不可用（隐私模式） | 读写各自静默失败，游戏照常可玩，不抛异常 |
| `localStorage` 内容被改成非法 JSON | 反序列化回退为初始状态，`pulls` 为 0，游戏从新档开始 |
| `localStorage` 里字段类型错误（字符串/负数/NaN） | 该字段回退为默认值，其余字段照常恢复 |
| `localStorage` 里混入未知成就 id | 未知 id 被丢弃，只有白名单内的 9 项被保留 |
| 档位候选池为空 | `applyPull` 抛出带档位 id 的明确错误，不返回静默错误结果 |
| 连点抽取按钮 | 演出进行中忽略额外输入，不叠加抽取次数 |
| 自动抽取期间切到别的标签页 | 定时器继续走，回标签页时状态一致，不出现重复抽取 |
| 浏览器不支持 AudioContext | 音效静默跳过，其余玩法不受影响 |

## 交互流程

1. **首屏**：卡面显示 `?`，图鉴 102 格全部未解锁，成就全部未解锁，统计全 0
2. **抽取**：卡面翻牌 → 档位名 + 字形 + 读音 + 释义；重复获得的字右上角不显示 NEW
3. **自动**：点「自动」或按 A，按钮旁显示 ON/OFF，卡面按节奏连续翻
4. **图鉴**：已获得的字显示字形并带档位配色，重复次数以 `×N` 角标显示，右下角显示 `已收集/102`
5. **成就**：达成时弹 toast 提示达成，其余显示为灰态
6. **重置**：点右上角「重置进度」→ 二次确认 → 清空存档并回到首屏状态

## 可访问性与适配

- 键盘：`空格` 抽取、`A` 切换自动
- 屏幕阅读器：卡面容器 `aria-live="polite"`，图鉴格子用 `title` 说明「已收集/未解锁」
- 动画：遵循 `prefers-reduced-motion`，命中时关闭翻牌与光晕动画
- 移动端：390px 视口无横向溢出，统计栏折成 3 列
- 语言：`html[lang]` 随切换同步

## 明确不做的事

- 不做多人对战、排行榜同步、账号系统
- 不做真实货币与抽卡商城（保持纯单机）
- 不引入真实维基百科频率数据集（当前用手工归类的生僻度百分位）
- 不做字形书写练习、笔顺动画等教育向功能
