# 立项评审 — Kanji Rush 汉字扭蛋

## 一句话定位

按汉字的真实使用频次决定稀有度、每抽一次演出就更快一档的汉字扭蛋网页小游戏。

## 为什么做它

同类做法（`kanjigacha.com` 一类的日文汉字扭蛋）已经把"抽字"这个点子用尽了，
剩下能比的只有**稀有度数据的权威性**和**演出节奏的爽度**——而这两点恰恰都能自己做得更好：

1. **数据要可解释**。同类站点的稀有度直接来自维基频率表，玩家看不懂为什么某个字是稀有的，
   只剩"抽到就是赚到"。本作把生僻度**显式建模成一个 0–100 的百分位**并标注在档位说明里，
   玩家能直接看到"生僻度 93 以上才是神话"，稀有度规则一眼可懂、可被讨论。
2. **节奏要自己控**。同类站点的加速节奏是写死的演出参数，玩家感觉不到"是我抽多了所以变快"，
   只觉得"这游戏有点吵"。本作把节奏做成**抽卡数的纯函数**（`tempoDelay`），
   并且在界面上实时显示当前间隔毫秒数，把"越抽越快"从一个副作用变成**可见的因果**。
3. **保底要透明**。同类站点普遍不公示保底阈值，玩家无法规划。本作把 60 抽保底做成
   面板上可见的 `12/60` 计数器，保底触发时有独立提示。

## 核心亮点

**"抽得越多，演出越快"这条曲线是可见的。** 玩家在界面上能同时看到三个数字：
抽取次数、当前间隔毫秒数、连击数。第一次抽是 1400ms 的从容，到第 100 抽变成 306ms 的手忙脚乱。
把一个常见的"加速"机制做成**玩家能读懂的数字**，是本作与同类最直观的差别。

**爽点在第三个瞬间。** 前 20 抽是"看看能抽到什么"；20–60 抽是"节奏上来了，停不下来"；
60 抽后保底兜底，传说卡出现时卡面走一次额外光晕脉冲 + 四音上行 + toast 提示，
连击计数同时跳动——三层反馈叠在同一个瞬间，是本作最想做好的一刻。

## 核心循环引擎

**主引擎：`progression-rng`（成长与随机奖励）** —— 快速期待节奏 + 里程碑跳变 + 规则解锁。

选它的理由：本作的每一个动作都在服务"下一次抽取的期待"，没有战斗、没有解谜、没有操作技巧。
玩家的成长曲线是**收集度**与**演出速度**两条线同时爬升。

- **快速期待节奏**：抽卡间隔从 1400ms 起，按 0.985 逐抽衰减到下限 180ms。玩家永远处在"下一张马上就来"的状态里。
- **里程碑跳变**：保底 60 抽必出传说；出传说/神话后进入 5 抽的 8 折加速窗口（`surge`），形成节奏上的小高潮与回落。
- **规则解锁**：图鉴 102 字按 5 档稀有度分层收集；分档分布条随抽取实时更新，玩家随时能看到"我今天运气如何"。

**辅助引擎：无**（不与第二类混用，避免目标线打架）。

本引擎的目标线与 Hard Fail：

| 目标线 | 本作怎么满足 |
| --- | --- |
| 每 ≤ 20–30 秒有可见成长 | 每次抽取都更新 4 个数字（抽取数 / 当前间隔 ms / 连击数 / 分档分布），加上图鉴点亮与成就进度 |
| 保底机制软化干 streak | 60 抽保底计数器在面板上可见（`12/60`），玩家知道自己在哪一抽会兜底 |
| 成长来源与消耗平衡 | 铜钱只来自抽取本身；本作无消耗点，是纯收集循环，平衡问题简化为"节奏不失控" |
| 数值增长之外要有规则解锁 | 5 档稀有度各自是独立的一组收集目标，达成 25/50/102 字逐级解锁成就 |

| Hard Fail | 本作怎么规避 |
| --- | --- |
| 重复点击毫无反馈 | 每次抽取都有翻牌动画 + 分层音效（1/2/3/4 音）+ 卡面更新 + 日志入列 + 连击跳动 |
| `NaN` / `Infinity` 溢出 | 抽取计数与间隔全部走普通数值；`tempoDelay` 有 180ms 硬下限 |
| 瞬间满级 | 102 字图鉴靠真实抽取积累；所有成就阈值都标注了可达的样本量（见「难度契约」） |

## 独特钩子

**Signature Twist（签名钩子）：稀有度不是随机标签，而是汉字真实使用频次的百分位映射。**

同类扭蛋游戏的稀有度来自**卡片分级**——「的」是一档，「龘」是另一档，玩家看不懂依据，也无从形成预期，只能等机器给结果。本作把"这个字在真实语料里有多罕见"直接建模成一个 0–100 的**生僻度百分位**，并且在档位说明里公开标注边界（普通 0–34、稀有 35–57、史诗 58–77、传说 78–92、神话 93+）。

于是玩家可以用**自己的中文语感预判概率**：中文使用者大概率知道哪些字常用、哪些字冷僻。抽卡从此不再只是"赌运气"，而是"赌自己的判断" —— 这是同类里少见、且直接把玩家已有知识变成玩法资产的做法。

落点：`src/logic.js` 的 `tierOf(kanji)`（纯映射，边界值可穷举断言），字库数据在 `assets/data.js`。

**Peak Moment（峰值时刻）：第 60 抽保底传说卡的五层反馈叠加。**

翻牌 3D 入场（`rotateY + scale`，420ms）+ 传说卡专属光晕脉冲（`surge` 8 折加速窗口同时点亮徽标）+ 四音上行音效 + toast 提示 + 连击计数同时跳动 —— 五层反馈压在同一个瞬间，是本作唯一的高潮时刻，也是 60 抽长跑的全部意义。

落点：`assets/app.js` 的 `renderCard()`（翻牌）/ `renderFever()`（光晕脉冲）与 `playFever()`（分层音效）。

## 参考调研

参考对象：`kanjigacha.com`（日文汉字扭蛋，同类直接对照），以及 `docs/research/opengame-catalog.tsv` 中的 `hanzi-brain-spot`（汉字脑洞找茬）与 `idiom-chain-pro`（成语接龙）。

| 调研项 | 结论 |
| --- | --- |
| 核心循环与签名张力 | 同类扭蛋的签名张力集中在"抽到稀有"的那一下，但同类的稀有度**不可解释**，玩家除了期待没有别的事可做，久了就退化成"抽卡机替我决定"。本作把张力前移到"下一次会是什么"：稀有度由字频决定，玩家能用自己的中文语感预判，每次抽取因此是一次小小的判断，而不是一次盲赌。 |
| 空间布局与信息可见性 | 本作的空间是"单卡居中 + 右侧三栏常驻"（图鉴 / 成就 / 最近抽取）。关键约束：**102 格图鉴必须能一眼看出"还差哪几个"**，锁定格不能完全不可见（否则玩家失去期待），因此锁定格保留暗色轮廓与 `·` 占位；卡面是唯一视觉重心，统计栏次之，侧栏信息密度服务于"下一个目标是什么"。 |
| 视觉基调 | 深色抽卡台 + 衬线大字号字形，字本身即是主视觉。五档稀有度配色**同时作用于卡面边框、卡面辉光、图鉴格子底色与角标**——一套颜色走四处，保证玩家在界面任何位置看到同一种颜色都对应同一档。 |
| 手感参数基线 | 抽卡间隔 1400ms 起，按 0.985 逐抽衰减，下限 180ms；传说/神话后 5 抽进入 8 折加速窗口；保底 60 抽；权重 n/r/sr/ssr/ur = 100/45/18/5/1（合计 169）。 |

## 独特玩法

**生僻度百分位**这个中间层。同类只有"稀有/普通"两档直觉，本作给出 5 档并且公开分档依据，
玩家能自己推断下一个字值不值得赌。配合 102 字的图鉴，收集路径有明确的"还差哪几个"信息差。

不算"同类里少见的全新机制"，但**把已有的随机收集玩法做出可解释的确定性**，属于差异化而非换皮。

## 表现力

- **视觉**：卡片式抽卡台。字形用衬线字体大字号居中，五档稀有度各有专属配色并同时作用于
  卡面边框、卡面辉光、图鉴格子底色与角标，形成一套统一的视觉语言。
- **动效**：翻牌用 `rotateY + scale` 的 3D 入场（420ms），出传说/神话额外走一次光晕脉冲。
- **音效**：全部用 WebAudio 现场合成，按档位分 1/2/3/4 音的上行音阶，零外部音频文件。
- **信息层级**：卡面是唯一视觉重心，统计栏第二，图鉴/成就/日志三栏作为侧边常驻面板。

题材本身（汉字）自带高对比度字形与文化辨识度，完全撑得起这个表现方案。

## 差异化

- **与仓库已有 6 款对比**：最接近的是 `element-forge`（元素合成），但那是**确定性合成**
  （点两下就有结果），本作是**随机抽取 + 稀有度期望**，核心情绪相反（探索 vs 构造）。
  其余 5 款分别属于钓鱼、方块消除、物理沙盒、程序化城镇，玩法品类完全不重叠。
- **与候选池对比**：候选池里的"像素画画板""元素周期表配对"都是**技巧/记忆**向，
  本作是**随机 + 收集**向，节奏模型（越抽越快）在这个品类里是独一份的。

## 可测性

核心玩法**全部可确定性表达**，不依赖计时器与动画：

- `tierOf(freq)` 是纯映射 → 分档边界值可穷举断言
- `pickTierByWeight(rng)` 接受注入的随机源 → 权重分布可用固定种子做统计断言
- `applyPull(state, pool, rng)` 是纯函数 → 保底、连击、图鉴累加都能逐步断言
- `tempoDelay(pulls)` 是纯函数 → 单调性可断言
- `updateAchievements(state, pool)` 是纯函数 → 成就解锁次数可断言

`src/logic.js` 不引用任何浏览器 API，全部规则集中在此，因此可被完整单测。
UI 层的"自动抽取""键盘操作""音效"由 Playwright 冒烟测试在真实 Chromium 中验证。

## 风险与代价

| 风险 | 触发条件 | 应对 |
| --- | --- | --- |
| 随机性导致测试不稳定 | 单测直接用 `Math.random` | 全部随机源可注入，单测统一用固定种子 mulberry32 |
| 加速过快导致玩家失控 | 间隔下限设得太小 | 下限锁在 180ms，且 `tempoDelay` 单调不增，不做加速回退 |
| 档位候选池为空 | 数据与阈值不一致 | `applyPull` 对空池抛出明确错误；单测断言每档非空 |
| 存档被用户手改后崩溃 | `localStorage` 内容不可信 | `deserializeState` 逐字段校验，非法值回退默认 |
| 演出太快看不清字 | 间隔压到 180ms | 保留 180ms 下限 + 出传说时 `surge` 加速仅持续 5 次 |
