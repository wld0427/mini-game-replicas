## 一句话定位

把鱼线甩进水里抢一个起竿窗口，然后靠读标记、按时机收放线，把 44 种鱼从五个水层里一条条钓进图鉴。

## 核心玩法循环

1. **抛竿** → 鱼线入水，等待一个 420–1900ms 的随机咬钩延迟（随水层缩短）。
2. **咬钩** → 浮标剧烈下顿，「咬钩了！快起竿」；同时开出一个 1350ms 的起竿窗口（卷线器 +130ms/级，水层 −70ms/级，下限 480ms）。
3. **抢起竿** → 窗口内点击起竿 → 进入遛鱼；窗口过期 → 鱼跑掉（`stats.misses` +1），结算不显示鱼种。
4. **遛鱼** → 竖轨上的标记持续上下漂移，中间一段绿区是甜区。玩家在甜区内点击收线：张力 −12、连击 +1、标记闪金；点错：张力 +14、标记变红。
5. **张力博弈** → 张力持续自然上涨（+3.5/s）。张力归零 → 上钩（进图鉴、给铜钱）；张力拉满 100 → 断线（`stats.escapes` +1），结算不显示鱼种。
6. **消费与再出发** → 铜钱升级四件装备（鱼竿/卷线器/饵/鱼篓），解锁更深水层与更高稀有档，回到第 1 步。

## 状态机

| 状态 | 含义 | 转入条件 | 转出到 |
| --- | --- | --- | --- |
| `idle` | 待抛竿 | 初始 / 结算后 | `waiting`（点抛竿或空格） |
| `waiting` | 已抛竿，等待咬钩 | 抛竿后 | `bite`（延迟到期） |
| `bite` | 鱼咬钩，起竿窗口开启 | 咬钩延迟到期 | `reel`（窗口内起竿）/ `result`（窗口过期） |
| `reel` | 遛鱼中 | 窗口内起竿 | `result`（张力归零或拉满） |
| `result` | 结算展示 | 遛鱼结束或起竿超时 | `idle`（点抛竿）或 `waiting`（直接再抛） |

非法转移的处理规则：

- 在 `idle`/`result` 之外点击抛竿 → **忽略**（按钮同时被置灰）。
- 在 `bite` 之外点击起竿 → **忽略**（按钮 `hidden`）。
- 在 `bite` 阶段窗口已过期才点击起竿 → **不进入遛鱼**，直接判负走 `result`（`doHook` 里的 `hookWindowOpen` 兜底判定）。
- 迟到的超时定时器在阶段已改变后触发 → **忽略**（`onHookTimeout` 首行检查 `phase !== 'bite'` 即返回）。

## 数据结构

```js
GameState = {
  version: 1,
  coins: 0,              // 铜钱
  totalEarned: 0,        // 累计收入
  upgrades: { rod: 0, reel: 0, bait: 0, basket: 0 },  // 四件装备等级
  dex: {},               // 鱼种 id → { count, bestCm, totalCm, firstAt }
  achievements: {},      // 成就 id → 解锁时间戳
  stats: {
    casts: 0,            // 抛竿次数
    catches: 0,          // 上钩次数
    misses: 0,           // 起竿超时次数
    escapes: 0,          // 遛鱼断线次数
    bestCm: 0,           // 历史最大个体
    tierCounts: { n: 0, r: 0, sr: 0, ssr: 0, ur: 0 },
  },
  pity: 0,               // 保底进度
  startedAt: null,       // 首次开玩时间
}
```

**持久化**：整体 JSON 存 `localStorage['angler-almanac-state-v1']`。
**脏数据回退**：`deserializeState()` 对任何非法 JSON、非对象、字段类型错误一律回退到 `createState()` 的默认值；`upgrades` 逐项 `min(max, safeInt(v))` 钳制；`dex` 中未知的鱼种 id 直接忽略；数值字段非有限数一律取 0。

**遛鱼瞬时状态**（不入存档，随阶段存在）：

```js
Reel = {
  tier, elapsed, marker, markerDir, sweetCenter, sweetWidth,
  tension, cooldown, pulls, good, lastHit, landed, snapped,
}
```

## 难度契约

三档难度必须用**同一套规则代码**跑通，不得为测试单独造一条"假逻辑"。

| 档位 | 必须成立 | 怎么验 | 现状 |
| --- | --- | --- | --- |
| 参考路线 | 一个「会玩的人」能稳定上钩 | 固定策略：咬钩立即起竿 → 标记进入甜区即点击收线，连续把张力打到 0 | 单测「会玩的玩家能把各档鱼钓上来」：5 个稀有度档各跑 200 次，上钩率 100% |
| 弱化路线 | 一个「水平一般的人」会挣扎或失败 | 显式降级输入：每次都在甜区**外**点击，张力单调上升 | 单测「乱点收线必然断线」：乱点序列必然触发 `snapped`，不会侥幸上钩 |
| 挂机路线 | 一个「完全不操作的人」会明确失败 | 零输入，固定 tick 数后断言终局为失败 | 端到端用例「D-3 遛鱼断线后产物卡不剧透」：零点击下张力按 +3.5/s 漂移，约 11.4 秒后断线进入 `result` |

补充说明：

- 「弱化路线失败」与「挂机路线失败」是两条**独立断言**，互不顶替：前者验证"乱玩会输"，后者验证"不玩不会白赢"。
- 随机触发类功能（稀有度、保底）在弱化路线上写明**样本量**：上表「会玩的玩家能把各档鱼钓上来」用 200 次/档的样本，而不是"通常能钓上"。
- 起竿窗口这一档也有三档：窗口内起竿进入遛鱼（参考路线）；窗口过期判负（弱化路线）；窗口过期后**点击起竿也不得进入遛鱼**（端到端用例 D-1 覆盖「起竿按钮消失、遛鱼面板不出现」）。

## 功能清单

| ID | 功能 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| F-001 | 抛竿与咬钩等待 | 抛竿后进入等待态，延迟到期触发咬钩 | 抛竿后 `stats.casts` 加 1 且状态为 `waiting`；咬钩延迟落在 420–1900ms 区间内 |
| F-002 | 起竿窗口与超时判负 | 咬钩后开一个有限窗口，过期即判负 | 卷线器 Lv.0 窗口等于 1350ms、Lv.2 等于 1610ms；咬钩后不操作等待窗口过期，阶段变为 `result` 且 `stats.misses` 计数等于 1 |
| F-003 | 起竿进入遛鱼 | 窗口内起竿进入遛鱼阶段 | 咬钩后立即起竿，阶段在 5s 内变为 `reel` 且遛鱼面板可见 |
| F-004 | 遛鱼甜区判定与张力 | 标记漂移、甜区判定、好时机降张力坏时机升张力 | 标记位置恒在 0–1 之间；甜区内点击使张力减少 12、甜区外点击使张力增加 14；张力等于 0 时判定上钩、张力达到 100 时判定断线 |
| F-005 | 遛鱼命中反馈与连击 | 命中/失手有视觉反馈并累计完美连击 | 甜区内点击后标记元素带 `is-hit` 类；命中后连击文案匹配「×数字」且计数等于 `reel.good` |
| F-006 | 上钩结算与失败呈现 | 上钩给钱入图鉴；起竿超时与断线都隐藏鱼种体长 | 上钩后 `stats.catches` 加 1 且图鉴解锁 1 格；起竿超时与断线两种失败下产物卡鱼种名等于「跑了」、体长等于「没能钓上来」 |

| F-009 | 保底机制 | 连续未钓到最深档则累计，达标必出最深档 | `pity` 达到 10 时下一次抽取的档位等于最深档且 `pityTriggered` 为 true；钓到最深档后 `pity` 归 0 |
| F-010 | 装备升级 | 四件装备可用铜钱升级，效果真实生效 | 升级扣钱且等级加 1；铜钱不足或已满级时拒绝升级并返回 null；卷线器每级使起竿窗口加 130ms |

### 可达性约束（随机触发类功能必须遵守）

凡是靠随机触发的功能（稀有度、保底、成就、掉落），验收标准必须能证明它**真的会被触发**，不能只验证「逻辑存在」。

本项目实例（渔汛录自己的历史问题）：`applyLoss(state, 'miss')` 写了、`stats.misses` 字段也写了，但因为 `onHookTimeout` 是**从未被调用的死代码**，「失手统计」这条功能在界面上恒为 0 —— 界面表现层根本没读过这三个字段。审计时靠「测试全绿但界面永远不变」发现。修复后补了 D-1/D-3 两条端到端用例，把「统计会变」写成可判定的断言。

## 边界与异常

| 场景 | 期望行为 |
| --- | --- |
| 咬钩后窗口过期才点起竿 | 判负进入 `result`，不进入遛鱼，`stats.misses` 加 1 |
| 超时定时器在阶段已改变后触发 | 忽略，不覆盖当前阶段 |
| 张力超过 100 | 钳制到 100 并判定断线 |
| 张力低于 0 | 钳制到 0 并判定上钩 |
| 甜区宽度为 0（极端参数） | 判定退化为「不在区内」，不会除零 |
| 全部鱼种被锁定（空档位） | 权重总和为 0 时退化为普通档，不抛异常 |
| 存档 JSON 非法 | 回退到全新默认状态，不崩溃 |
| 存档里含未知鱼种 id | 忽略该条，其余数据正常加载 |
| 存档里升级等级超过上限 | 钳制到该装备的 `max` |
| 饵等级为 5（等于上限） | 水层名正常显示「极渊」，不出现 `undefined` |
| `localStorage` 不可写（隐私模式） | 写入失败被捕获，游戏仍可正常游玩 |
| 浏览器不支持 `AudioContext` | 静音运行，不影响任何玩法逻辑 |

## 交互流程

1. 进入页面 → `idle`。可见：抛竿按钮、图鉴、装备、成就、统计。**不可见**：起竿按钮、遛鱼面板、产物卡。
2. 点抛竿 → `waiting`。抛竿按钮置灰，浮标入水，等待期场景区显示水层与幸运值。
3. 咬钩 → `bite`。浮标下顿、涟漪扩散、起竿按钮出现并脉冲，场景区显示剩余秒数。**此时起竿按钮是唯一可点的东西**（空格亦可）。
4. 起竿成功 → `reel`。遛鱼面板出现（竖轨标记 + 甜区 + 张力条），场景区显示鱼影与钓线。点击遛鱼面板任意位置 = 收线。
5. 遛鱼结束 → `result`。产物卡显示（成功显示鱼种体长与铜钱；失败显示「跑了 / 没能钓上来」），抛竿按钮恢复可用。
6. 结算后点抛竿或按空格 → 回到第 2 步。

**不该出现可点元素的状态**：遛鱼面板在非 `reel` 阶段必须 `hidden`；起竿按钮在非 `bite` 阶段必须 `hidden`；抛竿按钮在 `waiting`/`bite`/`reel` 阶段必须 `disabled`。
