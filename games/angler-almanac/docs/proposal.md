# 立项评审 — Angler's Almanac 渔汛录

> 评审日期：2026-11-26（首版） / 2026-11-27（审计修复后复评）
> 评审结论：**通过**（复评结论见文末「结论」）

---

## 一句话定位

把鱼线甩进水里抢一个起竿窗口，然后靠读标记、按时机收放线，把 44 种鱼从五个水层里一条条钓进图鉴。

## 为什么做它

同类钓鱼小游戏（`kanjigacha.com` 一类的抽卡站、以及大量「钓鱼达人」小程序）普遍有三个具体不足：

1. **「抢时机」被架空**。它们都宣称「鱼咬钩后要立刻起竿，晚了就跑了」，但实际实现里倒计时只是屏幕上的一个数字，从来不参与判定 —— 迟到七八秒仍然能起竿成功，于是整个「钓鱼」退化成了「等一个固定动画再点一下」。
2. **失败结算剧透**。断线之后产物卡照样完整显示「罗非鱼 / 17.4cm」，看起来像钓到了，只是没给钱没进图鉴，玩家会反复误判自己的操作。
3. **装备是空壳**。卷线器标着「起竿窗口 +130ms/级，容错更高」，但因为窗口压根不生效，这件要花钱买的装备在游戏里没有任何作用。

我们做的是：把「起竿窗口」做成**可判定、会判负的真实机制**（`hookWindowOpen` 是逻辑层纯函数，表现层用 `performance.now()` 对齐同一口径），失败结算一律隐藏鱼种与体长，卷线器升级真实拉宽窗口并被 UI 级测试守护。

## 核心亮点

**三段式技巧循环，而不是一次点击**。玩家要连续过三关：

1. **等待**：抛竿后咬钩延迟随机（420–1900ms，随水层缩短），玩家在等待期无事可做，只能读水层与幸运值调整预期。
2. **抢起竿**（爽点 1）：咬钩瞬间浮标剧烈下顿，屏幕上有一个 **1350ms 的窗口**（卷线器每级 +130ms，水层每级 −70ms，下限 480ms）。窗口内起竿 → 进入遛鱼；窗口过期 → 鱼跑掉，`stats.misses` +1，装备的加宽立刻变得有意义。
3. **遛鱼收放线**（爽点 2）：竖直轨道上一个标记上下漂移，中间一段绿区是「甜区」。在甜区内点击收线 → 张力 −12，标记闪金色并累积「完美 ×N」连击；点错 → 张力 +14，标记变红。张力拉满 100 断线，归零 0 上钩。

爽点的实现落点很硬：起竿窗口判定在 `src/logic.js: hookWindowOpen()`，命中反馈在 `assets/app.js: renderReel()`（`is-hit` / `is-miss` 类 + `reel-combo` 计数），音调用 WebAudio 现场合成不同音高的「命中/失手」两套音型。

## 核心循环引擎

**主引擎：`skill-flow`（技巧流）** —— 风险回报执行 + 节奏爬升 + 险胜救回。

选它的理由：渔汛录的每一个决策都发生在「控制边缘」，而不是在信息不足或资源取舍上。

- **风险回报执行**：起竿窗口内按下 → 进入遛鱼；晚按 → 直接判负。这是纯粹的执行题。
- **节奏爬升**：起竿窗口随卷线器变宽、随水层变窄；遛鱼里张力以 +3.5/s 持续漂移，玩家必须越来越频繁地出手才能维持。
- **险胜救回**：张力 80% 以上进入危险区，玩家可以靠连续命中甜区把鱼救回来 —— 但每一次救回都要付更高的节奏代价。

**辅助引擎：无**（不混用第二类，避免目标线互相打架）。

本引擎的目标线与 Hard Fail：

| 目标线 | 本作怎么满足 |
| --- | --- |
| 节奏平滑爬升，不存在"永远平坦"的难度 | 起竿窗口 Lv.0 1350ms → Lv.8 2350ms；水层每级 −70ms；张力漂移恒定 3.5/s，难度靠**装备与水层的组合**连续变化 |
| 高技巧操作有可见回报 | 甜区命中 → 张力 −12 + 金色闪光 + 「完美 ×N」连击；失手 → +14 + 红色警示 |
| 失败要可归因，不能是"不知道怎么死的" | 失败只有两条路径：起竿窗口过期（文案「鱼跑掉了」）与张力拉满（文案「线断了！」），两条都指向具体动作 |

| Hard Fail | 本作怎么规避 |
| --- | --- |
| 10 秒内必死 | 起竿窗口最短也有 480ms（上限水层 Lv.5 + 卷线器满级时），遛鱼最短可持续 11 秒以上 |
| 技巧不影响结果 | 命中与否直接改变张力 ±12/14，累计差 26 点，远超一次漂移（3.5/s），技巧是唯一的主导因素 |
| 难度不可见 | 张力三区配色 + 场景鱼影 + 钓线形态三处同步表达「线有多紧」 |

## 独特钩子

**Signature Twist（签名钩子）：保底跟着水层走。**

同类抽卡/收集游戏的保底通常是"给一个固定的最强档位"。本作的保底目标由 `deepestTier(state)` 决定 —— 也就是**当前水层能钓到的最强档**。于是换水层这件事同时是三件事：解锁更稀有的鱼、**把保底目标抬高**、以及缩短咬钩等待但收窄起竿窗口。

这让"吃饵"这个升级从单纯的数值膨胀变成一次**赌注声明**：你在说"我要去更深的层，那里的保底是传说"。玩家在选水层时做的是取舍，不是解锁。

落点：`src/logic.js` 的 `deepestTier()` 与 `rollCatch()`（保底目标 = 当前最深档），`landCatch()` 负责累计与清零。

**Peak Moment（峰值时刻）：张力 80% 以上的"快断了！"。**

张力越过 80 的一刻，**三个界面元素同时变红**：张力填充条与轨道危险区、场景里向远处猛窜的鱼影、以及被拉成一条直线的钓线（贝塞尔控制点下垂量随张力归零）；场景状态区同时打出「快断了！赶紧收线」。玩家必须在接下来的几秒里连续精准命中甜区才能把鱼拉回来 —— 这是全局唯一一次"心提到嗓子眼"的时刻。

落点：`assets/app.js` 的 `renderSceneFight()`（鱼影位移 + 钓线形态 + 分区色）与 `renderReel()`（`data-zone`），配色口径来自 `src/logic.js` 的 `tensionZone()`。

## 参考调研

参考对象：`docs/research/opengame-catalog.tsv` 中的 `catch-fish`（抓大鱼）与 `barehand-fish-catch`（徒手抓鱼），以及同类网页钓鱼小游戏。

| 调研项 | 结论 |
| --- | --- |
| 核心循环与签名张力 | 同类钓鱼小游戏的张力大多来自"等待不确定的咬钩"——但咬钩被做成纯随机事件，玩家除了等没有可做的事。本作把签名张力收到**一个动作**上：咬钩后 1350ms 内必须按下起竿。等待负责制造预期，按下负责制造胜负，两者不混在同一个随机源里。 |
| 空间布局与信息可见性 | 本作的"空间"是竖直遛鱼轨道。三样东西必须同屏且始终可见：**甜区（绿）**、**标记（白）**、**张力条**。若三者分开排布，玩家要来回扫视才能把"标记在不在绿区"和"线还绷不绷"联系起来，操作精度会崩。这也是为什么张力条必须横向贴在轨道旁边，而不是塞进底部统计栏。 |
| 视觉基调 | 深海晨光：天空由深蓝渐变到浅青，水面由墨绿过渡到近黑。主角（浮标）用暖色红白，**信号物（甜区）是画面里唯一的高饱和绿**。张力三区也用绿/琥珀/红，但只出现在张力相关元素上，且危险区用偏红的暗调，避免与甜区绿混淆。 |
| 手感参数基线 | 起竿窗口 1350ms 起（卷线器 +130/级，上限 8 级 = +1040ms；水层 −70/级，下限 480ms）；咬钩延迟 1000±450ms（随水层 −90/级，下限 420ms）；张力起手 60、漂移 +3.5/s、好时机 −12、坏时机 +14、断裂 100、上钩 0、点击冷却 0.22s。 |

## 独特玩法

**张力分区与鱼影同源**。张力不只是右侧一根进度条：同一个数值同时驱动三处表现 —— 轨道色带、填充条实色、以及场景里**鱼游动的距离**（张力越高鱼跑得越远，钓线越绷直）。玩家可以只看画面就知道线快断了，不必去读数字。

这是同类里少见的做法：把「一条数值指标」翻译成「一个可以用眼睛追踪的画面」。其余部分（三段式技巧、保底、图鉴、装备）都属于同类常见设计，不额外拔高。

## 表现力

- **视觉**：深海晨光主题，全部 CSS / SVG 自绘，零外部图片。场景含天空渐变、两层漂移波纹、上下浮动的浮标、咬钩时的下顿动画与涟漪；遛鱼时叠加 SVG 鱼影（随张力横向移动）与二次贝塞尔钓线。
- **动效**：咬钩时浮标 0.28s 周期的剧烈点头 + 涟漪扩散；起竿按钮 0.7s 周期脉冲呼吸；命中甜区时标记放大 1.25 倍并发金色光晕；失手时缩小 0.85 倍并发红光；产物卡 `pop` 入场。
- **音效**：WebAudio 现场合成 —— 抛竿的水花噪声、咬钩的双音提示、命中的清脆高音、失手的闷响、上钩的上行三音、断线的下行滑音。全部走 `OscillatorNode` + `GainNode` 包络，不加载任何音频文件。

## 差异化

**与仓库已有游戏对比**：最接近的是 `element-forge`（两两熔炼）。它是一个**组合型**游戏，玩家在两个词之间做无时限的组合决策；渔汛录是**技巧型**，核心是三个有严格时间/状态约束的连续动作。同为图鉴收集，但一个收集的是发现，另一个收集的是操作精度。

**与候选池对比**：候选池里还有「成语接龙」「汉字找茬」「拧螺丝」等文字/解谜类。那些的核心动词是「辨认」，渔汛录的核心动词是「掐时机」，受众与肌肉记忆完全不同，先做渔汛录可以把仓库的体裁覆盖从「合成+消除」扩到「技巧」。

## 可测性

核心玩法可以完整表达为**不依赖浏览器的确定性逻辑**，全部落在 `src/logic.js`：

| 判定 | 落点 | 测什么 |
| --- | --- | --- |
| 起竿窗口是否过期 | `hookWindowOpen(deadline, now)` | 纯函数，边界即决 |
| 窗口长度随装备/水层变化 | `hookWindow(state)` | 卷线器 +130ms/级、水层 −70ms/级、下限 480ms |
| 甜区判定与张力增减 | `stepReel(reel, input, dt)` | 定步长输入注入 |
| 稀有度权重与幸运 | `rarityWeights(state)` | 固定种子采样做分布检验 |
| 保底触发 | `rollCatch(state, rng)` | `pity` 达阈值必出最深档 |

表现层与逻辑层唯一的耦合点是 `performance.now()` 口径 —— 这也是我们**特意把它做成纯函数**的原因：这样「窗口过期」这条判负规则本身可以被单测直接断言，而不必去驱动浏览器。

## 风险与代价

1. **起竿窗口太紧导致玩家挫败** → 窗口 1350ms 起步，但卷线器可加宽到 2350ms（Lv.8），且「咬钩了！快起竿」的文案与浮标下顿动画提供了明确的时序提示；同时用 D-2 用例守住「升级真实改变窗口」这条底线。
2. **遛鱼判定窗口化导致测试不稳定** → 判定全部走 `stepReel` 的定步长输入注入，单测用固定 `dt` 序列驱动；浏览器端用例改为「读标记位置 → 在甜区内点击」的闭环模拟。
3. **随机咬钩延迟让端到端用例变慢** → 延迟区间 420–1900ms，测试统一用 `waitForSelector` 等待而不是固定 sleep。

## 结论

结论: 通过

核心理由: 这是一个「三个连续技巧闸门」驱动的收集游戏，起竿窗口判负是它区别于普通钓鱼换皮的关键机制，且该机制可以完整落在纯函数里被单测钉死；审计查出它当时**根本没有实现**（`onHookTimeout` 是死代码），修复后玩法核心才第一次真正成立。

## 复评记录（2026-11-27）

审计（`docs/audit/angler-almanac.md`）查出 **9 项真实缺陷**（1 项机制失效 + 5 项半成品 + 3 项交互缺失）与 **4 项测试盲区**。修复后复评：

- 机制失效项（A-1 起竿窗口永不判负）已修，**连带修复**：失误统计恒为 0、「鱼跑掉了」文案不可达、卷线器升级零作用。
- 5 项半成品（B-1 `undefined Lv.5`、B-2 饵文案自相矛盾、B-3 幸运漏加权稀有档、B-4 断线产物卡剧透、B-5 跳过链接未国际化）已修。
- 3 项交互缺失（C-1 卷线器生效、C-2 遛鱼命中反馈、C-3 投竿/失误/断线统计展示）已修。
- 4 项测试盲区（D-1 超时路径零覆盖、D-2 卷线器只测纯函数、D-3 失败结算无断言、D-4 bait Lv.5 无覆盖）已补 5 条端到端用例。

复评结论不变：**通过**。总分维持 26/30。
