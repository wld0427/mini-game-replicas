# 立项评审 — Element Forge 元素熔炉

## 一句话定位

把两个元素丢进熔炉、撞出新词条的**确定性合成**网页小游戏：表内配方可复现，表外组合按中文构词法原创造词。

## 为什么做它

同类做法（Infinite Craft 一类）把"合成"这个点子用在了**大模型随机生成**上：
玩家丢两个词，模型现编一个听起来沾边的答案。结果是——**同一对原料，两个玩家得到不同的东西**，
配方没法抄、进度没法比，图鉴收集也就退化成"看运气"。

本作要补的是这个缺陷，而且能补得更彻底：

1. **结果必须确定**。表内 102 条配方是硬编码的，`火 + 水` 永远等于 `蒸汽`；表外组合的结果
   由**配方散列**派生（不吃随机数），同样一对原料永远得到同一个结果。这让"抄配方给朋友"
   成为一个真实可用的社交动作，而不是一句空话。
2. **原创造词也要有语言学依据**。大模型会编出"火风龙"这种无意义的词；本作用**中文构词法**
   拆词素：取一个词的**定语**（作定语）+ 另一个词的**中心语**（作中心语），
   `水 + 星 → 水星`、`土 + 汽 → 土汽`。前者是真词，后者生硬但读得懂，
   这种"偶尔造出真词、偶尔造出怪词"的落差正是收集的乐趣。
3. **稀有度要能解释**。表内配方按元素本身多罕见手工分档；原创合成的稀有度则由**合成层数**
   决定——越深的层数越可能撞出史诗以上，权重表公开在设计文档里，玩家能自己推断。

## 核心亮点

**「确定性」和「无限性」同时成立。** 106 个正式词条全部可达（全部能被合成出来，没有孤岛），
但表外的组合空间是开放的：任意两个已发现的元素都能互熔，得到一个**名字由构词法生成**的新词条，
并且**永远只得到这一个**。玩家的体验是"我在造一门自己的语言"，而不是"我在抽卡"。

**原创词条和正式词条住进同一本图鉴。** 造出来的怪词和收录的正经词条并排显示，
正式词条 106 格 + 原创词条无限增长。图鉴因此是一个**混合的成就墙**：
玩家既在收集"水星""时间""意识"这类正经元素，也在收集自己造出来的"土汽""梦地"。

**层数是可见的进度条。** 基础元素是第 0 层，每熔炼一次 +1，最深第 10 层
（时间 → 化石 → 记忆 → 灵魂 → 意识）。界面上的「深度」读数把"我离顶层还有多远"变成一个数字。

## 独特玩法

**「定语 + 中心语」的中文构词引擎。** 同类只有"词 + 词 = 随机词"。本作把词素拆开再重组：
`水` 的定语是「水」、`星` 的中心语是「星」→ `水星`；`蒸汽` 的定语是「蒸」、`土` 的中心语是「地」
→ `蒸地`。重名时自动加增幅前缀（超/巨/太/古/梦/幻），原创词之间重名则追加序号。

这不算"全新机制"，但它把**已有的无限合成玩法做出可解释、可复现、可抄配方**的版本，
和仓库里其余 5 款（随机抽取 / 钓鱼 / 消行 / 物理 / 城镇）的情绪都不同。

## 表现力

- **视觉**：熔炉工作台布局。中央两个槽位像炼金坩埚，右侧图鉴 106 格按稀有度分色，
  正式词条与原创词条用同一种视觉语言，稀有度配色贯穿图鉴格、产物卡与配方手册。
- **动效**：熔炼产物卡入场用 `pop` 弹性缩放；原创词条额外带一枚「原创」角标，
  视觉上把"表内配方"和"现造的词"区分开。
- **音效**：全部 WebAudio 现场合成——熔炼按稀有度分 1/4/5 音上行音阶，
  每日灵感另有一组颗粒音，零外部音频文件。
- **信息层级**：产物卡是唯一视觉重心；右侧依次是图鉴 → 每日灵感 → 成就 → 配方手册。

题材（元素与造词）自带文化辨识度与词汇乐趣，完全撑得起这个表现方案。

## 差异化

- **与仓库已有游戏对比**：最接近的是 `kanji-rush`，但那是**随机抽取 + 稀有度期望**；
  本作是**确定性构造**，核心情绪相反（探索 vs 造物）。
  其余 4 款分别属于钓鱼、方块消除、物理沙盒、程序化城镇，玩法品类不重叠。
- **与候选池对比**：候选池里的"元素周期表配对""反应力测试"是**记忆/反应**向，
  本作是**构造 + 收集**向。

## 可测性

核心玩法**全部可确定性表达**，不依赖计时器与动画：

- `recipeKey(a, b)` 顺序无关 → `applyFusion` 的输入表命中可直接断言
- `composeImprovised(a, b, state, hash)` 只吃配方散列 → 同一对原料两次调用结果字符串相等
- `improvisedTierWeights(gen)` 是纯函数 → 层数与稀有度的关系可断言
- `applyDailyDraw(state, dateKey)` 只依赖注入的日期 → 上限、保底、跨日重置都可断言
- `computeGenerations(recipes, baseIds)` 是纯函数 → 层数表可穷举断言

`src/logic.js` 不引用任何浏览器 API，全部规则集中在此，因此可被完整单测。

## 风险与代价

| 风险 | 触发条件 | 应对 |
| --- | --- | --- |
| 原创词读起来像乱码 | 词素表覆盖不全 | 核心词条标注定语/中心语，其余回退到自身名称；怪词被明确定位为"原创"角标 |
| 原创词与正式词条撞名 | 玩家先造出"水星"再解锁正式水星 | 撞名时自动加增幅前缀或序号，存档里两者共存不冲突 |
| 早期图鉴太空、没得玩 | 起始只有 4 个基础元素 | 基础元素两两互熔立刻得到 6 个新词条；每日灵感每天补 5 个 |
| 每日灵感抽到已拥有的词 | 某档全部收集完 | 抽取优先在未拥有的同档里选；实在没有才回退到已拥有 |
| 存档被手改后崩溃 | `localStorage` 内容不可信 | `deserializeState` 逐字段校验，非法值回退默认 |
| 产物卡出现 `undefined` | 每日灵感没有"原料"概念 | 结果卡按来源分别渲染（合成显示配方，每日显示来源） |

## 结论

结论: 通过

核心理由：本作把"无限合成"这一品类里最被诟病的**不确定性**换成了**由配方散列派生的确定性**，
并用中文构词法给原创结果一个能读懂的语言学解释；106 个词条全部可达保证收集有终点，
而表外组合空间开放保证收集没有终点。核心逻辑全部纯函数化，可完整单测，表现空间充足。
