# 开发计划 — Element Forge 元素熔炉

## 总览

本轮目标：把存量首版的 Element Forge 补到**四道门禁全绿**，并且补的是**真功能**而不是补文档。

三个阶段串行推进，前一阶段的验收命令跑绿才允许开下一阶段。

| 阶段 | 目标 | 产出 |
| --- | --- | --- |
| 1 | 文档地基：立项评审 + 功能设计 + 开发计划 | `docs/proposal.md` `docs/design.md` `docs/plan.md` |
| 2 | 补真功能 + 补行为测试 + 补追溯标记 | `assets/app.js` `src/logic.js` `test/*.test.mjs` |
| 3 | 交付验收：双端截图人工核对 + 验收记录 + 部署 | `docs/acceptance.md` + 部署 URL |

## 阶段

### 阶段 1：文档地基

**做什么**：按 `docs/process/` 模板写三份文档，把 19 项功能清单定下来。

**产出文件**：`games/element-forge/docs/proposal.md`、`design.md`、`plan.md`

**验收命令**：

```bash
node scripts/design-review.mjs games/element-forge
```

**期望输出**：

```
✓ element-forge — 立项评审 / 设计文档 / 开发计划 齐备且达标

✓ 设计评审全部通过。
```

**完成标准**：设计评审退出码 0，且 `design.md` 的功能清单能被 `scripts/feature-trace.mjs` 解析出 19 个 F-ID。

---

### 阶段 2：补真功能 + 补行为测试

**做什么**：

1. 修 F-015：每日灵感产物卡的来源标注（消除 `undefined + undefined`）。
2. 做 F-010：配方手册条目可点击，一键把原料装回槽位。
3. 修 F-016：搜索无匹配与图鉴为空用不同提示。
4. 补 F-003/F-004/F-005/F-006/F-009 的**行为断言**（这五个逻辑函数此前零覆盖）。
5. 给 19 项功能在代码里加 `@feature` 标记、在测试里加 `@covers` 标记。
6. 门禁之外再自审一轮：核验另一会话审计报告（`docs/audit/element-forge.md`）指出的功能空洞，
   逐条修掉——每日保底跨日累计（否则永远攒不到阈值）、芯片显式可拖（否则拖拽是死代码）、
   产物卡补链式合成提示、搜索能查到未发现词条。
   **关键约束：断言必须走玩家真正会走的路径**，不许把状态伪造出来再断言。

**产出文件**：`games/element-forge/assets/app.js`、`src/logic.js`、`test/logic.test.mjs`、`test/smoke.test.mjs`

**验收命令**：

```bash
cd games/element-forge && node --test "test/*.test.mjs"
node scripts/review.mjs games/element-forge
node scripts/feature-trace.mjs games/element-forge
```

**期望输出**：

```
# tests 55
# pass 55
# fail 0

✓ 静态审查通过：检查了 1 个项目，未发现问题。

✓ 功能追溯矩阵完整：无缺失实现、无缺失测试、无缺失验收、无孤儿实现。
```

**完成标准**：三条命令全部退出码 0；功能追溯矩阵 19 项全部 ✅。

---

### 阶段 3：交付验收

**做什么**：
1. 桌面 + 移动双端截图人工核对（布局错位、遮挡、文字截断、按钮反馈），逐条写验收记录，部署并验证。
2. 截图核对中发现的问题必须**当场改代码**，不只写进「已知问题」。本轮实际修掉三处：
   - 雾家族 4 个元素共用 `🌫️` 且该字形渲染成无特征白块 → 重新分配字形；
   - 桌面左栏比右栏短约 900px，右侧拖出大片空白 → `.layout` 改网格区域排布，两栏配平；
   - toast 固定在 `top: 122px`，窄屏顶栏折行后正好压住「原料 A」槽位 → 改为固定底部居中。
3. 截图用「拉高视口再截」而非 Playwright `fullPage`，避免 sticky 顶栏的拼接伪影造成误判。

**产出文件**：`games/element-forge/docs/acceptance.md`、`docs/shots/*.png`

**验收命令**：

```bash
node scripts/gate.mjs games/element-forge
curl -s -o /dev/null -w '%{http_code}\n' https://<部署域名>/
```

**期望输出**：

```
  ✓ 静态代码审查 — 检查了 1 个项目，未发现问题
  ✓ 立项评审 + 设计文档 + 开发计划
  ✓ 功能追溯矩阵（设计 ↔ 实现 ↔ 测试 ↔ 验收）
  ✓ 全量测试
  ✓ 追踪表登记完整 — 6 款均已登记
  ✓ 标记为「已交付」的项目均通过门禁

✓ 总门禁通过。
```

**完成标准**：总门禁退出码 0；双端截图已人工看过并修掉发现的问题；部署后首页 200。

## 阶段门禁规则

- 阶段 1 不绿 → 不许写代码（否则功能清单会与实现脱节，追溯矩阵失去基准）。
- 阶段 2 不绿 → 不许写验收记录（没有测试背书的验收是假的）。
- 阶段 3 不绿 → **不许开始下一款游戏**。

## 风险登记

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 改产物卡渲染时破坏熔炼路径的显示 | 中 | 高 | 渲染分支用 `source` 显式区分，两条路径各写一条断言 |
| 配方条目改可点后误触发熔炼 | 低 | 中 | 条目用 `button` 并 `stopPropagation`，只填槽不熔炼 |
| 补 5 个逻辑函数的测试时写出「存在性断言」 | 中 | 高 | 每条断言都检查**返回值内容**（字符串相等、计数变化、权重关系），不检查函数是否定义 |
| 追溯矩阵出现孤儿实现（代码有 @feature 但设计文档没有） | 低 | 高 | 先定稿 design.md 再加标记，标记与清单一一对应 |
