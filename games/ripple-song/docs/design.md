# 功能设计 — 涟歌 Ripple Song

## 一句话定位

在一片会自己起伏的波场里，**你不能点亮目标，你只能移动波**——挪动波源，让干涉把共鸣点顶到最亮。

## 核心玩法循环

```
移动波源 ──▶ 波场重新演化 ──▶ 各共鸣点的振幅包络变化
    ▲                                    │
    │                                    ▼
    └──── 未全亮：看「差多少」再调 ◀── 全部点亮 → 驻波收敛（过关）
```

- **移动波源**：玩家唯一的操作（方向键 / 拖拽）。
- **演化**：波场按定步长 1/60 秒显式积分（`stepWave`），源驱动、礁石吸收、振幅包络衰减同时更新。
- **判定**：`evaluateTargets()` 比较各共鸣点的振幅包络与阈值，逐个点亮 / 熄灭。
- **过关**：所有共鸣点**同时**点亮 → 驻波收敛（Peak Moment）；倒计时归零仍未全亮 → 失败。

## 状态机

```
   ┌──────────┐  开始/继续   ┌──────────┐
   │   menu   │ ──────────▶ │ playing  │◀──────┐
   └──────────┘              └────┬─────┘       │
                                   │             │ 继续
              ┌────────────────────┼─────────────┘
              ▼                    ▼
        ┌──────────┐         ┌──────────┐
        │  won     │         │  lost    │
        │ 过关     │         │ 超时失败 │
        └──────────┘         └──────────┘
              └────────► menu ◄────────┘
```

- `menu` → `playing`：点「开始」或按空格。
- `playing` → `won`：所有共鸣点同时点亮（进入胜利用户的结算态）。
- `playing` → `lost`：倒计时归零且仍有未点亮目标。
- `playing` 内可 `P` / `Esc` 暂停（`paused` 态，冻结积分与计时）。
- `won` / `lost` → `menu`：点「再来一次」或「返回」。

## 数据结构

```js
// 波场：160 × 90 = 14400 格
Field = {
  w: 160, h: 90,
  u:      Float32Array,   // 当前位移
  uPrev:  Float32Array,   // 上一帧位移（显式积分的第二个历史量）
  uNext:  Float32Array,   // 下一帧位移（三缓冲轮转，零分配）
  env:    Float32Array,   // 振幅包络：近期峰值，峰值保持 + 衰减
  obstacles: Uint8Array,  // 1 = 礁石（吸收边界，u 恒为 0）
}

Game = {
  field: Field,
  sources: { x, y }[],       // 波源（可移动）
  targets: { x, y, id, peak, threshold }[],   // 共鸣点（不可交互，各带自己的阈值）
  threshold: number,         // 点亮阈值（振幅包络）
  timeLeft: number,          // 剩余秒数
  elapsed: number,
  lit: boolean[],            // 每个共鸣点当前是否点亮
  resonance: number,         // 共鸣值（0–1，= 全部目标包络之和 / 阈值和）
  state: 'playing' | 'won' | 'lost' | 'paused',
}
```

| 数据 | 位置 | 约束 |
| --- | --- | --- |
| 波场参数 | `src/logic.js` 常量 | `C² ≤ 0.5`（取 0.25）、源周期 24 步 ⇒ 波长 ≈ 12 格、阻尼 0.996 |
| 关卡生成 | `createLevel(seed, index)` | 同一 seed ⇒ 布局与目标完全一致 |
| 共鸣点 | `createLevel()` 产出 | 目标位置取自"标准解"模拟后包络的局部极大值 ⇒ **必然可被点亮**；每个目标带自己的阈值（标准解峰值 × 0.6） |
| 起点 vs 解 | `createLevel()` 产出 | `start` 是玩家开局站的位置，**必须不是解**（站在起点不能已经全亮）；`solution` 是隐藏的标准解 |
| 存档 | `serializeProfile()` / `deserializeProfile()` | 损坏时回退为初始档案 |

## 功能清单

| ID | 功能 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| F-001 | 波场数据结构 | 160×90 的位移 / 前帧 / 包络三份 Float32Array | `createField()` 的三数组长度均等于 14400；初始全部为 0 |
| F-002 | 定步长波动方程积分 | `u_next = (2u − u_prev + C²∇²u) × damp` | 同一初态连续积分 60 步两次，结果逐格相等；全场无 NaN / Infinity；振幅峰值不随步数单调增长 |
| F-003 | 波源驱动 | 相干正弦振子，周期 24 步，源格位移等于驱动值 | 源所在格的 `u` 等于 `A·sin(2πt/T)`；两个源同相位（同 `t` 值相等） |
| F-004 | 礁石吸收边界 | 礁石格恒为 0，波被吸收不穿透 | 积分后所有礁石格的 `u` 恒等于 0；礁石两侧的格不互相耦合（改一侧不影响另一侧） |
| F-005 | 振幅包络 | 峰值保持 + 每步衰减 | `updateEnvelope()` 后 `env[i] ≥ |u[i]|`；衰减后 `env` 单调不增 |
| F-006 | 共鸣点判定 | 每个共鸣点带自己的阈值（标准解峰值 × 0.6），包络越过阈值即点亮 | 包络低于阈值时 `lit` 为 false；超过阈值时为 true；阈值边界取 `≥` |
| F-007 | 关卡生成 | 布局 + 由标准解模拟产出的共鸣点 | 同一 seed 两次 `createLevel()` 的礁石与目标坐标完全相等；用标准解源位置模拟后，每个目标的包络都 ≥ 阈值 |
| F-008 | 波源移动 | 玩家唯一操作；越界被拒 | 移动后源坐标正确更新；越界移动返回 false 且源坐标不变 |
| F-009 | 移动不直接改判定 | 移动源只改变波场，不直接改共鸣点状态 | 调用 `moveSource()` 后，`lit` 数组内容不变；波场内容改变 |
| F-010 | 胜负判定与计分 | 全部点亮 → 胜；倒计时归零 → 负；**分数只在过关时结算** | 全亮时 `checkWin()` 为 true；仍有未亮且时间为 0 时 `checkLose()` 为 true；过程中 `score` 恒为 0，只有过关时才写入分数 |
| F-011 | 共鸣值与反馈量 | 0–1 的共鸣值驱动界面仪表 | 全部未亮时共鸣值等于 0；全部点亮时共鸣值等于 1；中间态严格落在 (0,1) |
| F-012 | 帧推进与计时 | 定步长累加器，单帧步数上限 | 传入 1000ms 的 `tick()` 后步数为 60（上限内）；超过上限时被截断且不发散 |
| F-013 | WebGL2 波场渲染 | 相位→色相、振幅→亮度（**低幅端走 gamma 曲线**，否则 1/r 衰减让远处全黑）、三通道色散、两级高斯泛光、暗角颗粒 | 着色器编译无 GL 错误、info log 为空；渲染后 canvas 中心像素非黑；`data-mode` 标记当前渲染路径 |
| F-014 | 2D canvas 回退 | WebGL2 不可用时渲染同一份波场 | 回退路径能画出与 WebGL 相同的格点数据；玩法不受影响 |
| F-015 | 三层合成 | WebGL 波场 → 2D 粒子 → DOM 标记 | 三个层容器同时存在且粒子层数量随波源移动而变化 |
| F-016 | 共鸣点标记层 | 点亮时爆开光环并给出文案 | 点亮某个点后其 DOM 节点带点亮类；全部点亮时所有目标都带该类 |
| F-017 | WebAudio 合成 | 零音频文件，现场合成底噪 / 移动轻响 / 点亮铃音 / 收敛和弦 / 失败下滑音 | 用户手势后音频上下文建立；移动与点亮时创建振荡器节点数 ≥ 1；整局不请求任何音频文件 |
| F-018 | 程序化混响与连击音阶 | 脉冲响应由代码生成（指数衰减 × 白噪）送入 ConvolverNode，外接 DynamicsCompressor；点亮音高随连击序号上行 | 卷积节点的脉冲响应长度 > 0；`noteFrequency(i)` 随 i 严格递增；不加载任何音频文件 |
| F-019 | 输入与手感 | 键盘方向键 / 触屏拖拽移动波源；点亮时震屏、过关时强震屏 | 方向键移动源坐标改变；拖拽同样能移动；点亮时海面获得 `is-shake-hit` 类、过关时获得 `is-shake-win` 类 |
| F-020 | 存档与多语言 | 关卡进度与语言持久化，zh/en/ja 三语 | 反序列化往返后关卡进度一致；损坏存档回退为初始档案；切换语言后 `html[lang]` 与界面文案同步改变 |

## 难度契约

三档路线**用同一套规则代码**跑（`stepWave` / `updateEnvelope` / `evaluateTargets` / `tick`），
不允许为测试造假逻辑。

| 路线 | 玩家行为 | 预期结果 | 判定方式（同一套规则） |
| --- | --- | --- | --- |
| **参考路线**（会玩的人能通关） | 知道"把波源挪到让波在所有目标处形成腹"的位置（关卡生成时记录的标准解位置） | 全部共鸣点同时点亮 → 过关 | 用 `createLevel()` 记录的标准解源位置跑 `tick()`，断言 `checkWin()` 在时限内为 true |
| **弱化路线**（水平一般的人会挣扎或失败） | 随机移动波源（固定种子） | 大概率点不亮全部目标 | **样本量 200 次随机走位**（每关每种子的步数固定），断言 200 次里成功点亮全部目标的次数为 0；且至少 1 次出现"部分点亮"（证明不是完全无解也不是太容易） |
| **挂机路线**（完全不操作会明确失败） | 波源不动，只等 | 倒计时走完 → 失败，**且不会无限挂机得分** | 固定源位置连续跑满关卡时限，断言 `checkLose()` 为 true、`score` 恒为 0；并断言没有任何共鸣点被点亮（否则说明不动也能赢） |

随机路线的样本量是 **200 次随机走位**（不是"可能会失败"）；
每一步都用与真实游玩完全相同的 `moveSource()` + `tick()` 路径。

## 边界与异常

| 情况 | 预期行为 |
| --- | --- |
| 波源被移动到网格外 | `moveSource()` 返回 false，源坐标不变，波场不受影响 |
| 波源被移到礁石格上 | 允许（源覆盖礁石），但礁石格仍是 0，源不会真的发声在该格 —— 实现上源格强制写驱动值 |
| 网格边界 | 采用吸收边界（边界外视为 0），波不会绕回 |
| 积分步数过多（标签页切回来） | 单帧步数上限封顶，剩余时间丢弃，绝不出现 NaN |
| 计时归零的瞬间正好全亮 | 先判胜再判负（同帧内胜优先） |
| 玩家站在起点就全亮了 | 关卡生成时检查起点：站在起点不能已经全亮，否则「只能移动波」这条规则形同虚设 |
| 共鸣点被礁石覆盖 | 生成器保证不重叠；读取时按现有坐标处理即可 |
| WebGL2 不可用 | 回退 2D canvas，玩法完全不变 |
| 着色器编译失败 | 捕获 info log 并回退 2D canvas，不白屏 |
| 存档损坏 / 字段类型异常 | `deserializeProfile()` 回退为初始档案，不抛异常 |
| 窗口极小（如 320px） | 棋盘与标记层不产生横向溢出，触屏拖拽仍可用 |

## 交互流程

1. **首屏**：标题 + 玩法三行说明 + 「开始」按钮；背景是缓慢起伏的演示波场（自动播放，不计入关卡）。
2. **关卡开始**：倒计时与共鸣值仪表出现在顶部；共鸣点以暗色菱形标出；波源是一个可拖动的亮点。
3. **移动**：方向键或拖拽波源 → 波面连续变形 → 共鸣点随包络变化而亮/暗。
4. **点亮**：某个共鸣点跨过阈值 → 爆开光环 + 清脆泛音 + 该点标记变为点亮态。
5. **过关**：全部共鸣点同时点亮 → 驻波收敛（画面短暂泛光抬升 + 和弦）→ 结算（用时 / 共鸣值 / 星级）。
6. **失败**：倒计时归零 → 波面塌成死水 → 结算（已点亮 N / 总数 M）。

## 打磨清单

| 项 | 现状 | 要做到 |
| --- | --- | --- |
| 目标点亮度 | 早期版本直接画目标色，不跟波场联动 | 目标亮度严格由包络驱动，禁止"标记亮着但波是暗的" |
| 波源可见性 | 波源只是场里一个点，找不到 | 波源带专属光环与拖拽手柄，键盘操作时同样高亮 |
| 共鸣值反馈 | 只有"亮/暗"两态 | 顶部仪表显示共鸣值百分比，让玩家看得见"差多少" |
| 驻波收敛 | 过关只是一次状态切换 | 全屏泛光短暂抬升 + 目标同时爆开，Peak Moment 要有分量 |
| 失败反馈 | 倒计时归零就结束 | 波面塌成死水（阻尼瞬间拉满）+ 结算说明差几个 |
| 波面观感 | 纯正弦条纹 | 相位→色相循环 + 振幅→亮度 + 三通道色散 + 两级泛光 + 暗角颗粒 |
| 降级路径 | WebGL2 失败会白屏 | 2D canvas 回退渲染同一份数据，玩法不受影响 |
| 波场远端发黑 | 2D 点源振幅按 1/r 衰减，直接映射的话整片海面只剩源附近一圈 | 着色器对振幅取 gamma 曲线（`pow(amp*3, 0.45)`）把低幅端抬起来，远处干涉条纹才读得出来 |
| 着色器程序结构 | 一个 program 只能挂一个片元着色器 | 亮部 / 模糊 / 合成各用独立 program，各编译各链接 |
| 粒子层每帧重建 DOM | 标记层每帧 `innerHTML=''` 会丢动画状态 | 只在点亮状态变化时重建，粒子用纯函数数组更新 |
| 音频没有用户手势 | 浏览器要求首次发声前有用户手势，直接建 AudioContext 会被拒 | 只在「开始」点击与首次方向键按下时 `ensure()`；未就绪时所有音效调用静默返回，不抛错 |
| 覆盖 buffer 的 setter 会弄坏节点 | 给 ConvolverNode 定义 `buffer` 自定义属性后，节点的 `connect` 解析失败 | 浏览器用例改为只留节点引用，断言时再读 `buffer.length` |
