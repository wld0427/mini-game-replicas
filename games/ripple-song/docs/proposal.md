# 立项评审 — 涟歌 Ripple Song

## 一句话定位

在一片会自己起伏的波场里，**你不能点亮目标，你只能移动波**——挪动波源，让干涉把共鸣点顶到最亮。

## 为什么做它

同类「摆放 + 结果涌现」的小游戏（`Mini Metro` 的线路调度、`Baba Is You` 的改规则）都有一个共同点：
玩家改的是**规则或布局**，结果由系统推导。本作把这条路线推到物理层 ——
玩家改的不是方块的位置，而是**波的发射点**，目标点的亮度完全由波场干涉决定。

**这类做法普遍的不足**是：推导过程不可见，玩家只能看到结果、看不到因果，
于是「我摆错了」和「规则就是这样」分不清，失败时没有信息可学。

本作的做法是：**波场本身就是界面**。
玩家在屏幕上看到的是一张实时起伏的波面（相位→色相、振幅→亮度），
共鸣点在哪、源该怎么挪，都是**看得见的物理**，不是隐藏的判定。
移动波源 → 波面立刻变形 → 目标点的亮度立刻变化，因果链在屏幕上闭合。

## 核心亮点

**亮��一：因果可见的干涉解谜。**
玩家拖动波源，两列波在礁石之间往返叠加，**驻波的腹与节实时显形**；
共鸣点从暗到亮，是波真的在那里叠加起来了，不是一句"判定失败"。
落点：`src/logic.js` 的 `stepWave()`（显式积分）与 `evaluateTargets()`（振幅包络阈值）。

**亮点二：不能直接操作目标。**
共鸣点是**不可交互**的 —— 你没法点亮它，只能让波去点亮它。
这把"目标导向的摆放"改成了"因果导向的实验"：
每次移动都是一次实验，结果是物理的、可复现的（同一关同一操作序列，结果完全一致）。

## 核心循环引擎

**主引擎：`puzzle-pressure`（谜题压力）**

- **目标线**：在倒计时结束前，让**全部共鸣点同时处于点亮状态**（振幅包络超过阈值）。
- **Hard Fail**：倒计时归零时仍有共鸣点未点亮 → 失败。**挂机必败**：
  波源不动 ⇒ 驻波形状不动 ⇒ 目标点的振幅不会越过阈值。

**辅引擎：`sandbox-explore`（沙盒探索）**

- **目标线**：关卡之外，玩家可在自由模式里摆源、摆礁石，看波场怎么变，
  把"共振"这件事本身当成玩具。
- **Hard Fail**：沙盒无失败；它是玩家的实验室，也是理解主引擎的手段。

## 独特钩子

**Signature Twist（签名钩子）：你不能点亮目标，你只能移动波。**

不是换皮装饰，而是一条**规则级的禁令**：共鸣点没有交互入口，
玩家的全部操作集合只有「移动波源」这一个动作。
于是"点亮目标"这件事必须经由物理路径达成 ——
它把一个摆放谜题变成了一个**实验谜题**。
落点：`src/logic.js` —— `moveSource()` 是唯一的玩家动作入口，
`evaluateTargets()` 只读波场振幅，不读任何玩家直接标记的状态。

**Peak Moment（峰值时刻）：驻波收敛。**

当波源被挪到某个特定间距上，两列波在礁石之间形成干净的驻波，
**多个共鸣点在同一瞬间一起亮到最亮**，画面上波面从杂乱涟漪收敛成规则条纹，
共鸣点同时爆开一圈光环。这是本作的高光时刻。
落点：`src/logic.js` 的 `evaluateTargets()` 全部返回 true 的那一帧，
以及 `src/logic.js` 的 `resonanceScore()`（共鸣值）冲到峰值。

## 参考调研

只记结论，不搬运源码与素材。

| 参考 | 核心循环与签名张力 | 空间布局与信息可见性 |
| --- | --- | --- |
| `Mini Metro` | 核心循环是「有限资源 → 线路调度 → 需求变化」，签名张力在于**信息不完全但足够**：玩家看不到所有乘客的需求，只能从站点形状与线路颜色反推 | 地图本身就是 UI：线路颜色 + 站点形状构成可扫读的全局视图；玩家从不迷路，因为**画面即状态** |
| `Baba Is You` | 核心循环是「改规则而不是改状态」，签名张力是**规则可被推理**：玩家发现"推"这个动词能作用于石头的那一刻，谜题从试错变成推理 | 规则用**文字直接画在场景里**，不靠说明面板 —— 信息可见性优先于信息完整性 |
| `Antichamber` | 核心循环是「在陌生空间里用直觉试出规则」，签名张力来自**视觉矛盾**（看起来不可能的空间其实可行） | 空间本身是谜题；玩家的进度是**理解**，而不是数值 |
| `Rez`（音画同步） | 核心循环是「射击 → 声画反馈 → 沉浸」，签名张力在于**反馈的即时性**：每一次命中都在同帧给出画面与声音的确认 | 反馈分层：底层波场、中层粒子、顶层标记；**层次对应信息的不同重要度**，而不是特效堆叠 |

结论落到本作：
1. **画面即状态** —— 波场实时渲染，玩家通过看波面就知道该怎么挪源；
   目标点用独立的标记层，亮度与波场振幅严格同源，不允许"标记亮着但波是暗的"。
2. **反馈分层** —— 三层合成（WebGL 波场 → 2D 粒子 → DOM 标记），
   每层只承载一类信息，避免信息淹没。
3. **因果即时可见** —— 移动波源到下一帧就要看到波面变化，延迟必须小于一帧的直觉阈值。

## 独特玩法

**「干涉即解法」：共鸣点的位置是一组约束，波源位置是唯一变量。**
关卡由布局（礁石 + 目标）定义，而**目标位置是从物理模拟里长出来的** ——
生成器先用"标准解"模拟一次波场，再把振幅包络的局部极大值取作共鸣点。
于是每关的目标都不是手摆的，而是**某一组波源位置的自然产物**；
玩家要做的是**反解**：找出那个让波面同时在所有目标处达到腹的位置。

配合「礁石吸收边界」，波在礁石间往返叠加产生驻波，
共鸣点因此分布在若干条等距带上 —— 视觉上就像一张要解的方程。

## 表现力

- **视觉**：WebGL2 实时波场。相位 → 色相循环（波沿传播方向"跑色"），
  振幅 → 亮度，三通道色散（像真实水面折射），两级高斯泛光，暗角与胶片颗粒。
  礁石以硬边暗块切入波面，让"波在这里被吃掉"一眼可见。
- **动效**：移动波源时波面连续变形（不是跳帧）；点亮共鸣点时爆开一圈光环；
  驻波收敛时全屏泛光短暂抬升；失败时波面塌成死水。
- **音效**：WebAudio 现场合成 —— 波场底噪（滤波噪声，音高跟随波源距离）、
  点亮共鸣点的清脆泛音（音高随共鸣点序号上行）、驻波收敛时的和弦垫底。
  零音频文件。

## 差异化

- **与仓库已有 6 款对比**：最接近的是 `ball-foundry`（落球坊），同为"确定性模拟 + 物理手感"，
  但 ball-foundry 的玩家是在**投喂物理世界**（扔球、堆叠、材质碰撞），
  本作玩家是在**读物理世界**（干涉、驻波、振幅分布）——
  ball-foundry 的乐趣来自"我造出了什么"，本作的乐趣来自"我算出了什么"。
  与 `element-forge` 相比，那款是组合生成的收集玩法，本作是**单次解谜 + 物理实验**。
- **与候选池对比**：候选池里的「元素周期表配对」「2048 变体」「反应力测试」都是纯规则或纯反应，
  没有"玩家操作一个物理场、结果由场的状态决定"这一层。

## 可测性

核心玩法**全部可以脱离浏览器确定性表达**，规则落在 `src/logic.js`
（不引用 document / window / localStorage / performance / requestAnimationFrame）：

| 规则 | 落点 | 可测的不变量 |
| --- | --- | --- |
| 波动方程积分 | `stepWave()` | 同一状态 + 同一输入 → 逐格结果完全相等；无 NaN / Infinity；能量不单调发散 |
| 波源驱动 | `applySources()` | 源点的振幅等于驱动振幅；相干源相位一致 |
| 礁石吸收 | `applyObstacles()` | 礁石格恒为 0；礁石两侧的波不互相穿过 |
| 振幅包络 | `updateEnvelope()` | 包络 = 近期峰值且随衰减下降；包络单调不减直到衰减 |
| 共鸣点判定 | `evaluateTargets()` | 包络低于阈值 → 暗；高于阈值 → 亮；阈值边界可判定 |
| 关卡生成 | `createLevel()` | 同一关种子 → 布局与目标完全一致；生成的目标必然可被"标准解"点亮 |
| 波源移动 | `moveSource()` | 越界被拒；移动后源坐标正确；**移动不直接改变任何共鸣点状态** |
| 胜负判定 | `checkWin()` / `checkLose()` | 全部点亮 → 胜；倒计时归零且未全亮 → 负 |

随机性一律走固定种子 mulberry32；波场积分是定步长 1/60 秒的显式积分，
与帧率无关 —— 所以「同一操作序列 → 同一结局」可被端到端断言。

**关键约束（不可动摇）**：波场模拟只在 JS 里跑，GPU 只负责把波场画出来。
绝不让 shader 成为规则的第二实现 —— 历史上反复出现"单测全绿但游戏有洞"，
根因就是规则写在了表现层或写了两份然后分叉。

## 风险与代价

1. **WebGL2 在部分设备不可用**。
   兜底：回退 2D canvas 渲染**同一份波场数据**，玩法完全不受影响（只是没那么好看）。
2. **定步长积分在低帧率下会变慢**（掉帧时波传播变慢，像慢动作）。
   兜底：累加器固定步长 + 单帧步数上限（超出的时间丢弃），保证不发散、不卡死。
3. **驻波解可能太刁钻，玩家解不出来**。
   兜底：关卡生成时用"标准解"验证目标确实可被点亮；并提供
   **共鸣值仪表**（实时显示各目标离阈值多远），让玩家看得见"差多少"。
4. **物理模拟的性能**（160×90 × 60 步/秒）。
   兜底：Float32Array + 单次遍历更新包络；目标点判定只读目标格，不做全场扫描。

## 结论

结论: 通过

核心理由: 「不能点亮目标，只能移动波」把摆放谜题变成了因果实验，
而波场实时渲染让因果链在屏幕上闭合 —— 这是同类摆放游戏普遍给不了的东西；
核心规则完全能落在纯逻辑层做确定性单测，且有 WebGL2 → 2D canvas 的完整回退路径，值得做。
