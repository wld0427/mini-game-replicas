## 本轮修掉的真问题（看图 / 实测才发现的）

| 问题 | 修法 |
| --- | --- |
| 合成着色器只看瞬时振幅 → 远处波按 1/r 衰减几乎全黑，整片海面只剩源附近一圈 | 对振幅取 gamma 曲线 `pow(amp*3, 0.45)` 把低幅端抬起来 |
| 一个 program 挂了三个片元着色器 → 链接必然失败 | 拆成亮部 / 模糊 / 合成三个独立 program |
| 粒子层每帧重建标记 DOM → 冲掉刚加的光环动画状态 | 只在点亮状态变化时重建 |
| 音频没等用户手势就建 AudioContext → 浏览器直接拒绝 | 只在「开始」点击与首次方向键时初始化 |
| 给 ConvolverNode 覆盖 `buffer` 的 setter → 节点 `connect` 解析失败、整条音频链断掉 | 只留节点引用，断言时再读长度 |
| 难度契约用例误标 `@covers F-020`（实为胜负判定） | 改标 F-010 |
| 2D 回退路径只做了弱断言 | 新增「拦截 WebGL2 → 断言 `data-mode=2d` + 画出波场 + 仍能移动」 |

## 难度契约的落地验证

三档路线**用同一套规则代码**跑（`stepWave` / `updateEnvelope` / `evaluateTargets` / `tick`），各有断言：

| 路线 | 判定 | 结果 |
| --- | --- | --- |
| 参考路线（会玩的人能通关） | 标准解源位置在时限内点亮全部目标 | ✅ |
| 弱化路线（水平一般的人会挣扎） | **200 次随机走位**（固定种子）通关次数 | ✅ 0 次 |
| 挂机路线（完全不操作会明确失败） | 不动波源跑满时限 | ✅ 判负且得分为 0、没有任何目标被点亮 |

## 已知问题

- **首屏波场铺开需要时间**：波按物理速度传播，玩家开局前几秒只能看到源附近一小圈涟漪。
  这是物理的真实表现（不是渲染 bug），但首屏的「壮观感」依赖玩家等上几秒。
- **headless 下 rAF 只有几帧/秒**（实测 ~3fps），自动化截图时波场传播明显偏慢；
  真实浏览器 60fps 下不受影响。浏览器断言已改为 `waitForFunction` 轮询而非固定 sleep。
- **关卡数目前只开放 5 关**（商店/关卡面板里的其余格子是锁态占位），
  后续关卡由 `createLevel(seed, index)` 按同一套生成规则产出，扩展不需要改规则代码。
- 无排行榜、无跨端存档同步。属「明确不做的事」范围。
