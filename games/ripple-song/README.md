# Ripple Song 涟歌

在一片会自己起伏的波场里，**你不能点亮目标，你只能移动波**。
挪动波源，让干涉把共鸣点顶到最亮。

> 原创实现。玩法结构致敬「移动波源 → 干涉 → 目标点亮」这一类物理解谜，
> 代码、文案、数据均为本仓库自研自绘，不含任何第三方素材。

## 玩法

| 机制 | 说明 |
| --- | --- |
| **波场** | 160 × 90 的波动方程场，定步长 1/60 秒显式积分（`u_next = (2u − u_prev + C²∇²u) × damp`） |
| **波源** | 玩家**唯一**的操作对象。方向键或拖拽移动，相干正弦驱动，周期 24 步 |
| **共鸣点** | 不可点击。振幅包络越过阈值才被点亮 —— 你没法直接点亮它，只能让波去点亮它 |
| **礁石** | 吸收边界，波撞上去被吃掉；礁石之间来回叠加形成驻波 |
| **驻波收敛** | 把波源挪到某个位置，多个共鸣点同时亮到最亮 —— 那就是这一关的解 |
| **关卡** | 目标点由「标准解」模拟产出，每一关都保证有解 |

## 架构约束（不可动摇）

> **波场模拟在 JS 里跑（`src/logic.js`），GPU 只负责把波场画出来。
> 绝不让 shader 成为规则的第二实现。**

`src/logic.js` 不引用任何浏览器 API（无 document / window / localStorage / performance /
requestAnimationFrame）。判定（点亮、胜负、计分）全部在逻辑层，
渲染层只读波场数据、不得参与任何判定 —— 否则规则会分叉，单测就守护不住。

## 运行

```bash
python3 -m http.server 8080
# 访问 http://127.0.0.1:8080/games/ripple-song/
```

纯静态页面，无构建步骤、无运行时依赖、不引用任何外部 CDN。

## 测试

```bash
cd games/ripple-song
node --test "test/*.test.mjs"
```

覆盖波场积分的确定性、礁石吸收、振幅包络、共鸣点判定、关卡生成的可解性、
波源移动的边界、胜负与计分、档案往返与脏数据回退、粒子模拟的纯函数性质，
以及**难度契约三档路线**（参考路线能通关 / 200 次随机走位 0 次通关 / 挂机必败且零分）。
浏览器用例还会真编译 WebGL2 着色器（断言 info log 为空）并读回画布中心像素证明确实画出了东西；
另有 **2D 回退路径**（拦截 WebGL2 后仍能渲染与操作）与 **端到端通关**（用方向键把波源
挪到标准解 → 全部共鸣点点亮 → 结算）两条关键用例。共 39 条测试。

> headless Chromium 需要 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`
> 才能拿到 WebGL2 上下文；拿不到时会自动回退 2D canvas，玩法不受影响。
